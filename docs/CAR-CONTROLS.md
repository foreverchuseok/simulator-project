# 카 탑 박스 · OPB · 하중 감지(포텐셜 미터)

참고: 로컬 `부품설계.pdf` 221–226페이지. 구현: `js/car-panels.js`의 `buildCarControls()`.

## 승객 버튼 직접 조작 (2026-10-02)

- 아래 과거의 OPB “외형만 구현” 기록보다 이 계약이 우선한다. `js/passenger-controls.js`가 승장 호출 6개(1층 상승·2/3층 양방향·4층 하강), 주/측면 OPB 층 버튼 8개와 열림/닫힘 4개를 연결한다. 형상·치수·취부 위치는 유지한다.
- `PartGlow.bind()`의 선택적 `{direct:true}`는 부품 메뉴와 호버 설명 없이 기존 발광 부품을 한 번 누르면 실행한다. 버튼의 1.5mm 눌림 복귀, 선택층 LED와 하단 운행바 등록 표시를 연동한다. 가까운 작은 버튼의 확장 터치 영역은 중심에 가장 가까운 대상을 고르며 불투명 벽 뒤 대상은 제외한다. 직접 조작 버튼의 연속 탭은 카메라 확대를 유발하지 않는다.
- 운행바와 3D 버튼은 같은 호출 대기를 공유한다. 서로 다른 층은 등록 순서로 운행하며 동일층 중복 호출은 합친다. 진행 중 목적지는 바꾸지 않고, 도착하여 문이 완전히 열린 층의 호출을 지운 뒤 개폐를 마치고 다음 층으로 간다. 승장 방향등은 누른 방향만 켜고 도착 시 해제한다. 현재층 호출은 착상 위치에서 개문/개방 시간 연장이다.
- 점검·비상정지·사고 시연·BYPASS·피트 사다리 미복귀 때 새 호출을 거부하고 대기 호출을 지운다. 실제 이동은 `moveElevator()`의 카문/승장문 잠금 조건을 그대로 거친다. 폐문 콜백에 호출 목적지를 남기지 않아 취소된 호출이 STOP 복귀 뒤 출발하지 않는다.
- 주/측면 열림·닫힘은 운행바의 동일 명령을 사용한다. 닫히는 중 열림은 현재 위치에서 개방으로 반전하며 이전 폐문 완료 콜백을 취소한다. 개방 중 다시 열림을 누르면 3.5초 개방 시간을 갱신한다. 이동 중·미착상 위치에서 개문하지 않는다. 정지 후 층 사이에 있는 카는 기존 `curFloor`와 같은 층 호출도 실제 착상 위치까지 이동할 수 있다.
- `EmergencyCall`의 카 주/측면·카탑·피트는 한 번 누르면 기존 통화 시뮬레이션을 즉시 시작한다. 설명 자막·음성, 노랑 연결 중 → 초록 통화 중, 기계실 인터폰 표시등과 다시 눌러 종료하는 흐름을 유지한다. 실제 외부 전화망 연결 기능은 아니다.
- 검증 도구: `node tools/verify_passenger_controls.mjs`. PC·390/320px 터치 에뮬레이션에서 실물 버튼 선택, 층 운행·개폐, 중복/연속 호출, 비상통화와 STOP 차단을 확인하고 `.shot-passenger-controls/`에 화면과 결과를 남긴다. 실제 휴대폰 조작·성능 확인은 별도다.

## 피트·카상부 점검운전 (2026-09-28)

- 기계실 제어반도 `#inspection-action-machine`으로 같은 UP·DOWN 홀드 운전과 리셋을 사용한다. 아이콘은 제어반 문이 완전히 열렸을 때만 내부 스위치 오른쪽에 나타난다. 닫기 시작 시 홀드 운전을 중단하고 패널을 접으며 INS는 유지한다. 다시 문을 열어 점검 아이콘을 누르면 이어서 조작할 수 있다. 리셋은 카상부처럼 최근접 층 복귀·문 1회 개폐이며 삼각키·호출 연출은 없다. 곰은 기계실 바닥에 머물며 카와 카메라를 추종하지 않는다.
- 제어반 문 개폐 아이콘은 상부 회생제동 장치 위에 배치한다(`js/control-panel.js`). 내부 점검 아이콘·곰 손 위치는 GLB의 `upperLayout`·공용 축척에서 파생한다. `js/inspection-stations.js`의 상대 버튼 오프셋은 `blender/scripts/control_panel_sicon.py`의 `left`·`bp`·UP/COMMON/DOWN 배치와 동기화해야 한다. 모델·스위치 형상은 변경하지 않는다.
- 기계실 전용 검증은 `node tools/verify_machine_inspection.mjs`다. 문 개폐별 아이콘 표시·닫을 때 즉시 정지·PC/390px 터치 홀드·작업자/카메라 고정·최근접 층 복귀·비상정지 취소·화면·PC 프레임을 확인한다. 실제 모바일 기기 조작·성능은 별도 확인 대상이다.
- 기계실 구현 검증(2026-09-28): 전용 검증과 기존 `verify_inspection_return.mjs` 모두 통과, 브라우저 오류 0건. PC 1200×850 동일 제어반 시점의 대기/점검 상태 중앙값은 16.7/16.7ms, p95는 16.8/16.8ms였다. PC·390px 스크린샷에서 상부 문 개폐 아이콘·내부 스위치 오른쪽 점검 아이콘·세 조작 버튼을 확인했다.
- `js/inspection-stations.js`가 피트 스위치와 카상부 스위치에 `#inspection-action-pit`·`#inspection-action-car` 아이콘을 붙인다. 카상부는 후속 요청에 따라 좌측 체대 **윗면**에 길이 방향으로 눕혀 설치한다. 원본 모델의 +Z 조작면을 월드 +Y로 돌리며 STOP은 왼쪽이다. 취부 좌표 원본은 `js/elevator.js`의 `carFrameGrp.userData.inspectionMount.topY`다.
- 두 스위치는 기존 `models/gltf/pit_inspection_station.glb`(원본 `blender/scripts/pit_inspection_station.py`)를 공유한다. 카상부는 피트 모델을 복제하여 동일 크기·디자인을 유지한다. 인출선은 GLB `cableExit`에서 시작해 체대 앞을 따라 카탑 박스의 기존 공용 인입구로 들어간다. 기존 7회로의 배치·종점은 유지하며 새 점검선만 인입구 내부에 추가했다.
- 아이콘 클릭 시 INS로 전환하고 승강곰이 가까운 위치에서 접근한 뒤 `UP`·`DOWN`·`리셋`을 표시한다. 접근 완료 후 홀드 운전이 가능하다. 카상부 작업자와 카메라는 카의 수직 이동을 함께 따르고, 피트 작업자는 피트 바닥에 남는다. 모델은 COMMON과 방향 버튼에 손을 대며, 실제 속도·문 접점·리미트·로프 갱신은 기존 `ui.js` 점검운전을 사용한다.
- 손 뗌·포인터 취소·키보드 해제·포커스 상실·탭 숨김·화면 크기 변경·패널 접기에서 즉시 정지한다. 같은 아이콘 또는 메뉴/Esc로 접으면 INS를 유지하며 같은 아이콘으로 다시 연다. 자동 복귀는 옆의 `리셋`으로 시작한다. 승장문 발 받침과 점검운전은 동일 곰을 동시에 사용하지 않는다. 기존 `hall-reset`의 전체 리셋은 유지한다.
- 리셋 연출 원본은 `js/inspection-return.js`다. 피트: 곰이 1층에서 긴 삼각키를 4회 왕복 조작(매회 클릭음, 문짝 이동 0) → 호출판으로 이동 → 실제 호출버튼 모델을 2초 누름/LED 점등 → 1500Hz 확인음 → 카 1층 복귀 → 문 1회 개폐 → 정상 AUT. 카상부: 최근접 층 복귀 → 문 1회 개폐 → 정상 AUT이며 키·호출 장면은 없다.
- 자동 복귀는 `rescueToNearestFloor()`의 선택적 `floor`·`onArrive` 인자를 사용한다. 기존 호출의 최근접 층·개방 기본값은 유지한다. `setInspectionMode(false,{recover:false})`로 중복 착상을 막는다. 복귀 중 운전/점검 입력은 잠그고 비상정지는 유지한다. 비상정지 시 키 복귀·호출등 해제·예약 이동 취소 후 리셋 재시도를 기다린다.
- 우상단 고장·점검 메뉴와 구형 AUT/INS 패널·모바일 MODE 독을 제거했다. 승강곰 안전모의 `KOELSA` 표기는 `js/mascot.js`에서 모자 곡면을 따라 만든다.
- 복귀 검증: `node tools/verify_inspection_return.mjs`. 체대 윗면 취부의 위치·회전·스케일, 피트 키 4회 동안 문짝 이동 0·호출 길게 누름·확인음·문 1회 개폐, 카상부 최근접 층/이미 착상한 경우, 키 조작·복귀 운행 중 비상정지 취소 및 390px 터치를 확인했다. 브라우저 오류 0건이며 취부·복귀 시점·모바일 버튼 스크린샷도 확인했다.
- 마무리 재검증(2026-09-28): 위 복귀 검증과 `verify_inspection_stations.mjs`·`verify_portrait_hud.mjs`·`verify_inspection_reset.mjs` 모두 통과했다. 동일 PC 1200×850 카상부 시점에서 신규 형상 숨김/표시/곰 조작 프레임 중앙값은 모두 16.7ms, p95는 16.8/16.7/16.8ms였다. 실제 모바일 기기 성능 결과를 의미하지 않는다.
- 검증: `node tools/verify_inspection_stations.mjs`. PC·390px 터치, 홀드/키보드/취소, 회로 상태, 곰 복귀·카 추종, 승장문 작업 배타성·전체 리셋과 스크린샷을 확인했다. `verify_portrait_hud.mjs`의 320/360/390/412px·화면 회전·층 호출 및 `verify_inspection_reset.mjs`의 PC/터치·문 재잠금·사다리·BYPASS·UCM·조속기 복귀도 통과했다. 실제 휴대폰 조작·성능은 별도 확인 대상이다.

## 카 상·하부 배선 정리 (2026-09-19, 아래 과거 배선 설명보다 우선)

- 사용자 표시 사진 224933/224945/2249481 기준으로 천장 중앙을 가로지르는 배선과 느슨한 대각선을 없앴다. `js/car-wiring.js`가 카 로컬 경로·짧은 직각 굽힘·검은 전선·고정 새들·카탑 박스 인입 좌표의 공용 원본이다. 고정부품은 생성 시 한 번 만들고 반복 클립/받침은 인스턴싱한다.
- 천장은 토보드 바깥의 뒤쪽·왼쪽 가장자리를 따라 배치한다. 카탑 박스 바로 아래에서만 토보드를 넘어 동일 높이로 인입한다. 하부는 보강채널 아래와 외곽 프레임을 따라가고 수직 배선은 외판 모서리로 올린다.
- 사용자 후속 정정: PVC형 보호 부시는 카탑 박스 바로 아래의 **큰 원형 인입구 한 개**에만 둔다. 전체 배선은 검은 전선으로 표현하고, 안전장치·보조 OPB·이동케이블 정션·하중·메인 OPB·바이패스 경광등·도어 제어반의 7회로를 한 묶음으로 모아 인입한다. 기존 7개 개별 글랜드는 제거했다. `carTopBox.userData.entryHole`은 단일 구멍, `entries`는 그 안의 회로별 카 로컬 종점이다. 구멍 지름 50mm와 전선 굵기는 시각화용이며 전기회로 구현 범위는 바꾸지 않는다.
- 메인/보조 OPB의 외판 통과부는 실제 서비스 홀과 고무 부시를 만들었다. 도어 제어반 공급선은 기존 박스 옆면 대각 연결을 제거하고 하부 공용 인입구에 연결한다. 도어 모터선은 헤더 뒤쪽으로 정리하며 가동 문짝의 멀티빔 여유선·해제 와이어는 유지한다.
- 현재 코드의 하중 감지는 `carLoadSwitch_30/50/100/110` 네 스위치다. 각 리드를 취부 선반 앞쪽으로 돌려 작은 분기함에서 합류시키고 `loadSensorHarness` 전선으로 올린다. 아래 PM1/PM2 기록은 과거 구현이며 이번 배선 작업에서 센서 형상이나 작동을 교체한 것은 아니다.
- 실내 상자 오류: 도어의 `batchHardware()`가 인스턴싱한 고정대의 단위 BoxGeometry를 일반 메시처럼 병합해 카 중앙에 1m 상자를 만들었다. `isInstancedMesh`/`isSkinnedMesh`를 병합에서 제외해 원래 작은 고정대만 남긴다.
- 검증: `node tools/verify_car_wiring.mjs`. 직각 경로, 검은 전선, 천장 중앙 비움, 천장 부품 간섭, 외판·플랫폼·하중 취부선반 관통, 단일 실제 구멍/보호 부시와 7회로 인입, 고정대 인스턴싱 유지 및 실내 병합 상자 부재를 확인한다. `.shot-car-wiring/`에 상부·하부·박스 확대·측면·실내 화면과 JSON을 저장한다. 실제 모바일 조작·성능은 별도 확인 대상이다.

## 현재 외형

- 카 탑 박스: 상부 난간 왼쪽 앞 안쪽의 금속함, 뚜껑 이음, 난간 체결 브라켓 4개, 하부 케이블 인입.
- OPB: 출입구 리턴 실내면에 금속 세로 판넬, 검정 표시부, 원형 호출 버튼, 1–4층 버튼, 열림/닫힘 버튼, 하부 서비스 커버. 사용자 요청에 따라 표시 숫자는 고정된 4다. 현재 운행층 표시나 클릭 조작과는 연결하지 않았다.
- 하중 감지(LOAD-CP): 224–226p 18.5 포텐셜 미터 설치의 **A 타입** 대각 취부. `carOverloadAssembly` 안에 `carLoadSensor_PM1`(좌·전방, -X/+Z)과 `carLoadSensor_PM2`(우·후방, +X/-Z) 2개. 각 센서는 플랫폼 측면 채널(X ±1.18)이 세이프티 플랭크 위에 얹히는 모서리에서, 플랭크 웹에 붙인 ㄱ자 취부 브라켓 → 라이너 → 센서 몸체(플런저 위) 순으로 쌓이고 M6x30 볼트·와셔·너트 2조로 고정한다. 플런저 상단은 채널 하단(-S.CAR_H/2-0.085)에 접하며 `userData.pressMm = 3`(225p 눌림량 2–4mm)을 기록한다. 2026-09-11 사용자 지시로 223p의 하중 스위치 4조를 이 방식으로 대체했다(226p: POTENTIAL METER / LOAD CELL / NO USE 중 택1). 하중 값 계산이나 과부하 운행 차단은 구현하지 않았다.
- 센서 배선: PM2 리드는 플랭크 후면을 따라 좌측으로 와서 플랭크 밑을 돌아 PM1 리드와 합류한다. 합류 하니스는 플랫폼 밑 → 좌측 채널 바깥 → 좌측 외판 바깥(장애인 OPB 하니스와 20mm 이격) → 카 탑 박스 하부로 올라간다. 실제 연결 대상은 도어 인버터 GT-DINV 보드의 PM1/PM2 커넥터(226p)이지만 도어 오퍼레이터가 아직 없어 카 탑 박스에서 끝낸다.
- 모든 부품과 배선은 카 부모 그룹을 따라 이동한다. 추락방지 안전기 GLB의 작동 샤프트·리프트·웨지·스프링·클램프 노드 계약, 로프, FSM은 변경하지 않는다.

## 222–223페이지 전기 연결 관계 메모

도면의 카 탑 박스 보드에서 메인 OPB로 COP–CJB 케이블이 연결된다. 도면 표의 메인 연결 표기는 CN_T1/T2/T4/T15/T19이며, 보조 OPB는 CN_T16, 장애인 OPB는 CN_T17을 통해 CAN 통신 케이블로 연결된다. 메인 OPB와 장애인 OPB 외형을 배치했으며 전기 동작은 연결하지 않았다.

## 장애인용 측면 조작반 (2026-09-11)

- 디자인: [현대엘리베이터 NEO 공식 카탈로그](https://www.hyundaielevator.com/upload/product-catalog/k_neo.pdf) PDF 6페이지의 OPDNB210 금속 표판·원형 버튼·노란 호출 버튼을 참고해 4층용 가로 배열로 재구성했다. 제품의 정확한 치수 복제는 아니다.
- 배치: `carAccessibleOPB`, 불투명 -X 벽의 실내면, 마감바닥에서 모든 버튼 중심 1050mm(2026-09-27 사용자 승인: 850mm 연속 손잡이와의 간섭을 피하도록 200mm 상승). 진입방향은 -Z이므로 -X 벽은 진입 우측이다. 버튼 1–4, 열림, 닫힘, 비상통화 총 7개. 손잡이와 겹치지 않으며 출입구 모서리로부터 400mm 이상 떨어진다.
- 기존 850mm 배치 검토 근거: [편의증진법 시행규칙 별표 1 제9호](https://www.law.go.kr/LSW/flDownload.do?flSeq=46378893)의 조작설비 높이 0.8–1.2m, 휠체어 조작반 0.85m 내외/진입 우측/가로형/손잡이 비간섭을 반영했다. 링크는 2018-02-09 개정 별표이며 이번 작업은 조작반의 형상·배치 기준 적용이다. 건축허가일별 승강기 전체 검사 적합 판정은 하지 않는다.
- 점자: 국립국어원 [점자 편의시설 표준 지침서](https://m.korean.go.kr/common/download.do?c_file_name=2c57877a-7f17-4eda-af71-718b05358b71.pdf&file_path=etcData), 6.4–6.6에 따라 버튼 하단 부착형으로 통일했다. 층 숫자는 수표와 숫자, 기능은 개·폐·호출로 표기한다. 점형은 [한글 점자 표기](https://korean.go.kr/front/page/pageView.do?mn_id=205&page_id=P000302)를 참고했다. 점간격 2.5mm, 자간 6mm, 지름 1.5mm 반구 돌기 형상이다.
- 현재 기존 OPB처럼 외형만 구현했다. 실제 눌림·층 선택 점등·음성 안내·비상통화 동작은 미구현이므로 전체 장애인 검사기준 충족으로 간주하지 않는다.
- 검증: `node tools/verify_car_panels.mjs --accessible`. 1050mm 높이, 실내 방향, 불투명 벽, 손잡이 비간섭, 출입구 이격, 점자판 수와 확대 렌더 확인.

## 하중 감지 메모 (223p 스위치 vs 224–226p 포텐셜 미터)

223페이지는 하중 스위치를 세이프티 디바이스 취부홀에 고정하고 감지 볼트가 해당 하중에서 스위치에 접하도록 조정한 뒤 COP 보드 CC26에 연결하는 방식이다. 224–226페이지 18.5 포텐셜 미터 설치(LOAD-CP)는 A 타입 또는 B 타입으로 센서 2개를 대각 취부하고, 눌림량 2–4mm를 라이너로 맞추며, GT-DINV 보드의 PM1/PM2 커넥터에 연결한 뒤 HHT 메뉴 26 CAR LOAD ENABLE에서 POTENTIAL METER를 선택한다. 0% 부하 시 CAR LOAD 값 500–1000, 50% 부하 시 2048 이하가 기준이다. 모델은 2026-09-11부터 A 타입 포텐셜 미터 외형만 두며 223p 스위치 형상은 두지 않는다. 데이터 값 표시·과부하 판정은 미구현이다.

검증: `node tools/verify_car_panels.mjs`(전체) 또는 `--load`(하중 감지 확대). PM1/PM2 대각 배치, 측면 채널 밑 위치, 플런저-채널 접촉과 눌림량, 플랭크 웹 양면 취부, 하니스가 카 탑 박스에 닿는지, 4층 구성, 판넬 간극과 층별 추종을 확인한다. `--load`는 `.shot-car-panels-overload/pm1/pm2/load-wiring.png`를 남긴다.
