# ROADMAP — 웹 시뮬레이터 개발 순서

사용자 합의: 2026-09-17. 전체 순서와 인계 상태는 이 문서에서 관리한다. 실제 구현 계약은 각 부품 문서와 현재 코드를 따른다.

## 확정한 방향

- GitHub + Vercel 웹 배포를 유지한다. 직원 약 40~50명, 예상 동시 접속 1~2명의 현장·간단 교육 용도다.
- 직원은 같은 주소로 접속한다. APK 전환과 엔진 교체는 현재 범위에 포함하지 않는다.
- 새 부품보다 부드러운 운행, 관찰하기 쉬운 화면, 모바일 조작을 먼저 완성한다.
- 정밀 부품은 유지하되 전체 운행·부품 관찰·고장 학습에 필요한 상세 수준을 구분한다.

## 현재 단계 — 웹 최적화

진행 순서는 다음과 같다. 상세 실행 계획은 로컬 `PLAN.md`에 둔다.

1. 기준 측정: 기기·브라우저·해상도·시점·품질 설정을 기록하고 정지·시점 이동·운행·기존 과속 시연을 비교한다. 실제 목표 휴대폰과 성능 기준을 확정한다.
2. 로프 갱신: 운행 중 매번 생성·폐기하는 형상을 재사용하는 방향으로 개선한다. 로프 경로와 카·균형추·시브 연동을 보존한다.
3. 렌더링: 반복 부품과 재질 공유, 고정부품 묶음, 그림자 범위와 해상도 등을 측정 결과에 따라 개선한다.
4. 화면 구성: 기본 배경을 단순화하고 전체 운행·부품 관찰의 상세 수준을 구분한다. 정밀 원본과 가동부 계약을 보존한다.
5. 사용 경험: 모바일 UI·카메라 구도를 정리하고 운행·표시 속도·소리의 일관성을 검토한다.
6. 통합 확인: 실제 모바일과 PC에서 기본 운행 및 기존 안전장치 동작을 확인하고 성능 결과를 남긴다.

## 인계 상태

- 최신 배포 운영 합의(2026-09-19, 이전 보류 지시보다 우선): 수정·검증 후 커밋·푸시하여 자동 배포를 재개한다. 배포 삭제는 자동 실행하지 않고 사용자가 “5개 빼고 삭제”라고 요청할 때만 한다. 총 5개를 남기되 `agwrtmqr3`(5월 11일), `ec4kw7x2u`(8월 9일), `f54ocyc82`(9월 6일)는 변화 과정 비교용으로 반드시 보존한다. 나머지 2개는 현재 서비스 배포와 월별 변화를 볼 수 있는 대표 배포를 우선한다. 현재 Vercel 자체 Retention은 별도 설정이며 이번 합의만으로 변경한 것은 아니다. 사용자에게 CLI 삭제 후 사용량이 크게 줄었다는 확인을 받았다. 상부 전면벽 수정도 검증을 마쳤으며 이번 커밋으로 배포한다.

- Vercel 배포 정리(2026-09-19): 사용자 로그인 및 명시적 선택 후 `47iit3r1z`, `d5cgu0ymr`, `456x58nge` 3개를 CLI로 삭제했다. 변화 과정 비교용 `agwrtmqr3`(최초), `ec4kw7x2u`(중간), `f54ocyc82`(최근)와 현재 서비스 `8zynpc3jm`을 보존한다. 이 4개는 사용자 요청 없이 정리하지 않는다. 삭제 후 목록 4개와 `simulator-project-ecru.vercel.app`이 `8zynpc3jm`의 Ready 배포에 연결됨을 확인했다. 영구 삭제·사용량 감소까지 확인한 것은 아니다. 상부 벽 수정은 로컬에 있고 새 푸시·배포는 아직 하지 않았다.

- 상부 전면벽 보완: 사용자가 상부 높이는 적절하다고 확인했고, 로비 캐노피와 기계실 슬래브 사이에 누락된 승강로 전면벽을 요청했다. `shaftOverheadFrontWall`을 기존 벽의 폭·두께·재질로 연결했다. 로비 천장 높이와 카 상부 여유는 유지한다. `verify_overhead.mjs`에 벽 하단·상단·내측면 접합 검증을 추가했다.
- 벽 검증: Live Server에서 최상층 후면 화면을 확인하고 접합·기존 상부 치수 검증을 통과했다. 동일 PC·1100×1000·동일 최상층 시점에서 벽 숨김/표시를 각 3회 비교한 정지 프레임 중앙값은 모두 약 16.7ms, 호출 2,627→2,633회·삼각형 564,058→564,070개다. 실기기 검증은 하지 않았다. 로컬 결과는 `.shot-overhead/report.json`과 `after.png`다.
- 배포 운영 변경: 사용자 요청으로 Vercel 저장공간 정리 가능 여부를 확인할 때까지 새 푸시·배포를 보류한다. 사진 사용량은 Deployment Storage 7.84/10GB. 현재 PC에 Vercel CLI 인증 정보가 없어 삭제는 실행하지 않았다. 사용자가 `npx vercel login` 후 프로젝트 대시보드 주소를 제공하면 현재 서비스 배포를 보존하며 과거 배포·보관 설정을 확인한다. `remove --yes`는 확인 생략 옵션이며 즉시 영구삭제 옵션으로 안내하지 않는다. 정리 가능 여부가 확인되기 전에는 사용자가 배포를 담당한다.

- 상부 보정 성능: 같은 세션에서 변경 전/후 각 3회 재측정했다. Radeon Graphics / Chrome 149 / 1280×850 / DPR 1 / 그림자 켬, 카메라 `(18,6.724,21)`·타깃 `(0,6.724,0)` 고정. 정지·회전·운행 중앙값은 전후 약 33.3ms, p95는 정지·회전 약 33.4ms 및 운행 50ms로 같은 수준이다. 기본 호출 3,928→3,944회, 삼각형 819,266→823,058개다. 원본 `.shot-rope-performance/overhead-before.json`, `overhead-after.json`. 이전 날짜의 16.7ms 기록과 직접 비교하지 않는다. 모바일 성능은 사용자 후속 확인이 필요하다.

- 2단계 전 상부 공간 보정: 사용자 사진의 최상층 정상 정차 장면을 기준으로 `OVERHEAD`를 3.70→4.77m로 복원했다. 이 상수는 최상층 바닥부터 기계실 기준 바닥까지이며 슬래브 하면까지는 4.525m다. 카 천장 위 공간은 1.10→2.17m, 난간 상단 위 공간은 약 1.247m다. 층 정지점·카/균형추 이동 범위·종단 스위치는 유지하고 기계실·권상/편향/조속기 시브·레일 상단·천장 배선을 연동시켰다. 기존 6단 브라켓에 상부 지지 한 단을 추가했다. 완충기 압축 조건의 검사기준 적합성 판정은 이번 범위가 아니다.
- 상부 검증: `verify_overhead.mjs`에서 전후 기계실 메시 538개가 동일하게 +1.07m 이동하고 카·균형추·난간·정션박스·종단 스위치가 불변임을 확인했다. Live Server 전후 스크린샷은 `.shot-overhead/`, 권상로프 25개 위치의 기존 형상 대비 최대 오차 3.32e-9m와 왕복 운행 통과, 이동케이블·종단 검사 54/54 통과, 과속 시연·RST·구출 운전 통과. 케이블 검사 도구는 다른 도구와 같은 `--enable-gpu`로 셰이더 초기화 오류를 해결했다. 실기기 최상층 화면·조작 확인은 남아 있다.

- 사용자 후속 확인: 배포된 확대·더블탭 카메라 개선에 대해 “양호해 잘되었어”라는 확인을 받았다. 조작감 확인으로 기록하며, 기기별 FPS 측정이나 모든 안전장치 검증 완료를 뜻하지 않는다. 다음은 기본 운행·안전장치·표시 속도·소리의 통합 점검이다.

- 카메라 검증 기록: Live Server 캐시를 비운 `verify_view_modes.mjs camera-live`에서 6개 프리셋·배경 복원·PC 더블클릭·800×1280/1280×800/412×915 터치 더블탭·핀치 구분을 통과하고 근접 화면을 확인했다. `verify_overspeed.mjs --shadows --detail-view` 통과. `verify_rope_performance.mjs camera-after`의 동일 PC·1280×850·픽셀 비율 1·그림자 켬·3회 측정에서 정지/회전 중앙값 16.7ms, 운행 33.3ms, p95 33.4ms로 직전 studio-after 기록과 같은 수준이다. 호출 3,928회·삼각형 819,266개, 브라우저 오류 0건. 실기기 성능 결과를 뜻하지 않는다.

- 모바일 카메라(2026-09-19): 사용 기준을 Galaxy S22 이상 / Chrome으로 변경한다. 사용자 확인으로 S22+는 원활하며 S7 FE는 저성능 참고 기기로 둔다. 일반 카메라 최소 거리 0.04m, 근접 클리핑 0.002m를 허용하고 부품 더블클릭·더블탭으로 표면 앞까지 부드럽게 접근한다. 직접 조작하면 접근을 중단하고 전체 운행 버튼으로 복귀한다. 배경·숨긴 부품은 제외하며 핀치·드래그·비상 열쇠·과속 시연과 입력을 분리한다. PC 및 3종 화면 크기의 터치 에뮬레이션에서 접근·핀치 구분·프리셋 복귀와 과속 시연·RST·구출 운전을 검증했다. 실제 S22에서 새 카메라 조작 확인은 남아 있다.

- 가독성 조정(2026-09-19): 사용자의 ‘흰 배경·흰 구조물이 겹쳐 보인다’는 피드백을 반영했다. 기본 관찰 배경은 청회색 그라데이션, 바닥은 중간 명도 청회색으로 조정하고 노출과 주변광·보조광을 줄여 구조물의 면·윤곽과 노랑/파랑 안전색을 구분한다. 4×256 배경 텍스처를 재사용하며 추가 3D 배경·후처리는 없다. ‘주변 풍경’은 원래 바닥·하늘·안개·노출·조명까지 복원한다. 카 내부 프리셋은 문 안쪽, 피트는 난간을 피한 후면 시점으로 보정했다. 전체 운행·카 내부는 세로 화면 거리 확대에서 제외해 과도한 후퇴와 벽 밖 이동을 방지한다.
- 가독성 검증: Live Server 캐시 비운 새로고침 후 `verify_view_modes.mjs studio`로 6개 시점·배경/조명 반복 복원·부품 표시 보존과 800×1280·1280×800·412×915 터치 화면을 확인했다. 프리셋 검증은 GSAP의 시작 대기 중인 트윈까지 종료를 기다린 뒤 촬영한다. `verify_shadow_cache.mjs studio`의 정지/시점 이동 재계산 0회, 변경 6종 그림자 픽셀 차이 0. 같은 PC·해상도·시점·그림자 조건의 각 3회 전후 결과는 정지/회전 중앙값 약 16.7ms, 운행 약 33.3ms, p95 약 33.4ms로 전후 동일하다. 배경 패스 추가로 호출 3,927→3,928회, 삼각형 819,264→819,266개. 원본은 `.shot-rope-performance/studio-before.json`, `studio-after.json`, 화면·전환 검증은 `.shot-render-performance/studio-views.json`과 PNG. 실기기 성능 검증은 여전히 남아 있다.
- 화면 구성 구현(2026-09-18): 기본 배경은 승강기·진입 광장·평면 바닥만 표시한다. `outdoorLandscape` 아래에 지형·풀·꽃·개울을 묶고 주변 건물·하늘 돔과 함께 숨긴다. `setDetailedBackground()`와 카메라 메뉴의 ‘주변 풍경’으로 원래 풍경·바닥 재질·하늘·안개를 복원할 수 있다. 풍경 형상은 최초 로딩에 생성하며 이번 작업은 렌더 비용 개선이지 초기 생성·다운로드 비용 개선은 아니다. 부품·로프·센서의 상세 형상과 표시 상태는 유지한다.
- 관찰 화면: 카메라 메뉴를 ‘전체 운행’과 ‘부품 관찰’로 구분했다. 기존 기계실·피트·카 내부에 카 상부·조속기 프리셋을 추가하고 선택 상태를 표시한다. 관찰 시 근접 확대를 허용하고 전체 운행으로 돌아오면 원래 근접 제한을 복원한다. 프리셋 연속 선택은 이전 카메라 이동을 취소하며 과속 자동 시연 중에는 관찰 프리셋이 카메라를 덮어쓰지 않는다. 세로 화면 프리셋은 시선 방향을 유지하며 거리를 늘린다.
