## 1. 사용자 요구사항 핵심 정리 & 보존 계약

### 1-1. 요구사항 4가지
1. **기존 `시연` 메뉴 유지**: 오른쪽 `시연` 아이콘 목록(`#m-demo`)과 안내창(`#m-demo-preview`, 2026-11-21 재탭 닫기 포함)은 그대로 유지한다.
2. **모바일 3D 부품 직접 활성화 부활 (오터치 방지 2단계)**:
   - 모바일에서도 3D 부품을 직접 탭해 반응하게 한다.
   - 단, 과거처럼 탭하자마자 즉시 시연/동작이 실행되지 않도록 **1탭 → 부품 강조 + 글씨가 작고 아담한 팝업 표시 → 팝업 안 버튼 탭 시 실행** 구조로 만든다.
3. **모바일 게임 수준의 세련된 활성화·반짝임 연출**:
   - 사람들이 "저기 뭐가 있을까?" 호기심을 갖고 눌러 보도록 **모바일 게임처럼 반짝이고 디자인이 살아 있는 활성화 표현**을 적용한다.
4. **시연 중 일시정지 & 언제든 첫 화면 정리**:
   - 시연 도중 언제든 일시정지할 수 있고, 추가 조작(사용자 제안: 한 번 더 누르기 등)으로 **원래 첫 화면·정상 상태로 깔끔하게 정리·복귀**할 수 있어야 한다.

### 1-2. 절대 보존 계약 (구현 시 깨지 말 것)
- **오른쪽 `#m-demo` 시연 메뉴** 및 `js/mobile-demo-guide.js` 하단 자막 유지.
- **PC 기존 조작**(`PartGlow` 호버 툴팁·클릭 메뉴·설비 직접 조작·`desktop-hud.js`) 유지.
- **색상 이력 존중**: `js/part-glow.js:11` 기준, 사용자는 2026-09-30에 **푸른빛 발광을 반려하고 금색 계열 유지**를 확정했다. 기본 팔레트는 금색/샴페인 골드 톤을 축으로 삼는다.
- **물리·모델·치수 불변**: `const S`, FSM(`ELEVATOR_STATE`), 로프/시브/균형추 연동, GLB 노드명·피벗은 변경하지 않는다.
- **성능 기준**: 기준 기기(갤럭시 S22 이상 폰) 실측 환경에서 기본 화면(현재 약 2,360 드로우콜) 대비 호출·CPU 저하를 유발하지 않아야 한다.

### 1-3. 사용자 확정 사항 (2026-11-22)
1. **색상**: 금색 단일 톤(1안) 확정. 민트·푸른빛 금지.
2. **전체 보기(원거리)**: 겹침 억제 + 대표 부품만 표시. 확대·시점 이동 시 세부 부품이 나타남(Phase 1 범위).
   - **Phase 1 구현 메모**: 비콘을 부품 중심에 두면 부품 자체·벽에 가려지므로, **경계상자 윗면 + 카메라 쪽으로 약간 띄워** 배치한다.
3. **일시정지**: A안(`❚❚ 일시정지` → `[▶ 계속]` + `[⌂ 첫 화면]`) 확정. 우상단 `×`는 삭제하지 않고 유지(Phase 3 범위).
4. **확대(제3안 확정)**:
   - 부품 첫 탭 → 소형 팝업 즉시 표시(지연 없음)
   - 700ms 안에 같은 자리 재탭 → 팝업 닫고 그 부품으로 확대(기존 "두 번 탭하면 가까이" 안내 유지)
   - 천천히 재탭(> 700ms) → 팝업만 닫힘
5. **비-시연 설비 일괄 원상복구**: 2차로 보류.
6. **구현 순서**: Phase 2(모바일 소형 팝업·터치·선택 1개 부품 금색 강조) 먼저 완료 후 Phase 1·Phase 3 순차 진행.

### 2-2. 모바일에서 꺼져 있던 이유와 숨은 함정 4가지
1. **전면 잠금 (`js/part-glow.js:217, 247, 445`)**:
   - `touchLocked()`가 `MobileHUD.isMobile() && !CharacterWalk.active`일 때 `true`를 반환한다.
   - 이로 인해 모바일 일반 화면에서는 `syncPart()`의 발광 목표치가 `0`(빛 완전 꺼짐), `pointerup`은 즉시 `return`(탭 완전 차단) 상태다.
2. **함정 ① — `touchLocked()`만 풀면 설비 조작 오터치 재발**:
   - `isOperatingControl` 분기(`part-glow.js:357`)가 팝업 없이 곧바로 문을 열거나 사다리를 펼치거나 비상키 패널을 연다. 모바일에서는 설비 조작 부품도 반드시 2단계 팝업을 거치도록 분리해야 한다.
3. **함정 ② — 실행 깊이 불일치 (2단계 vs 3단계)**:
   - 과속 조절기·ARD·종단 스위치는 `#part-menu` 항목 탭 시 즉시 시연이 시작되지만, 로프브레이크(개문발차/상승과속)·권상기 주브레이크는 `#part-menu` → 별도 설정창(`#rope-brake-panel`, `#brake-compare-panel`) → 시작 버튼의 **3단계**를 거친다. 모바일 소형 팝업에서는 조건 선택과 실행 버튼을 한 카드에 합쳐 **모든 부품 2단계**로 통일해야 한다.
4. **함정 ③ — 터치 제스처 충돌 2종**:
   - **드래그 허용치 부족**: `js/part-glow.js:437`의 탭 취소 기준이 `6px`이다. 2026-11-05 승곰이 체험 S22+ 실측에서 모바일 손가락 탭은 `8~14px` 흔들림이 흔해 `6px` 기준은 잦은 무반응을 유발한다(승곰이는 `14px`로 해결함). 또한 멀티터치(핀치 줌) 시작 시 탭 무효화 방어가 없다.
   - **더블탭 확대(`bindCameraFocus`, `js/ui.js:1377-1454`)와 충돌**: 모바일에서 700ms·64px 이내 2회 탭하면 3D 지점으로 줌인한다. 단일 탭으로 팝업을 열면 더블탭의 첫 탭에 팝업이 먼저 튀어나와 두 번째 탭을 가로채거나 UX가 어색해진다.

### 2-3. 가장 중요한 공학적 제약 — 모바일 GPU/CPU 성능 병목
`js/adaptive-quality.js:3-4`와 `temporary/fps/after-noidle-phone-q0.json` 실측에 따르면:
- 기준 기기인 갤럭시 S22+(`idle=0`, `quality=0`) 기본 전체 시점은 **CPU(WebGL 드로우콜) 병목**이다(최적화 적용 후 기본 화면 약 **2,361 드로우콜**, CPU 58.7ms, DPR을 2→1.25로 낮춰도 FPS가 오르지 않음).
- **현재 `PartGlow.render()`(`js/part-glow.js:475-495`)를 모바일에 그대로 켜면 발생하는 문제**:
  - 활성 부품 1개당 독립 `THREE.Scene` + **`renderer.clearStencil()`** + 최대 28메시 × **3패스(`rim`, `inner`, `outer`)** + `Points(sparkle)` = **부품 1개당 최대 85 드로우콜 + 스텐실 클리어 1회**.
  - `ScreenCull`(`js/screen-cull.js:4`)은 메인 `scene`만 컬링하며 `PartGlow`는 건드리지 않는다.
  - 전체 보기에서 조속기·로프브레이크·승장문 비상키 4층 등 6~10개 이상 부품이 동시 활성화되면, **수백 개의 추가 드로우콜 + 모바일 타일 GPU(Adreno/Mali) 스텐실 버퍼 플러시 오버헤드**가 발생해 기준 기기(갤럭시 S22 이상)에서 심각한 프레임 드랍과 발열이 생긴다.
  - 시각적으로도 원거리에서 여러 부품이 동시에 두꺼운 금색 테두리로 번쩍이면 세련된 게임이 아니라 **산만한 화면**이 된다.

### 2-4. 시연 중 일시정지·초기화 컨트롤 파편화 진단
현재 모바일 시연 화면에는 제어 수단이 4곳에 흩어져 있다.
- **우상단 `×` (`#demo-exit`, `js/demo-exit.js`)**: 13종 시연 전체와 준비 단계를 페이지 리로드 없이 즉시 취소 → 정상 착상·폐문·전체 보기 복귀. `window` 캡처 단계에서 시연별 입력 차단을 선점한다.
- **하단 바 `#demo-pause` (`js/demo-pause.js`)**: 시연 일시정지/재개 + 자유 3D 회전·확대 관찰. **단, 완충기(`BufferDemo`)와 문 이탈방지(`RetentionDemo`)는 `js/demo-pause.js:99`에서 `#demo-pause`를 숨기고 대신 하단 자막 우측(`#m-demo-guide-action`, `js/mobile-demo-guide.js:148`)에 정지 버튼을 따로 둔다.**
- **하단 바 `#m-demo-exit` (`시연 종료`)** 및 **상단 `#ucm-exit` (`종료 · 정상 복귀`)**: 우상단 `×`와 역할이 중복된다.
- **비-시연 상태의 설비 조작 미정리**: 사용자가 3D 부품 탭으로 사다리 펼침·제어반/분전함 열림·승장문 비상키 개방·조명 켜기 등을 해 둔 상태에서는 `DemoExit`가 활성화되지 않아 한 번에 "원래 첫 화면으로 정리"하는 경로가 없다(`기타 설정 → 처음 상태로`는 전체 페이지 리로드).

## 3. 영역별 설계 제안 (TO-BE)

### 3-1. 영역 1 — 모바일 게임형 부품 활성화·반짝임 비주얼 (2-Tier 하이브리드)

모바일 게임(탐험형 3D 퍼즐·인터랙티브 뷰어)의 정석은 **"대기 상태는 초경량·절제된 반짝임으로 호기심만 자극하고, 선택한 1개 부품만 풀 퀄리티로 빛내는 것"**이다.

#### 제안 구조: 2-Tier LOD 발광 아키텍처

| 상태 | 비주얼 표현 (모바일 게임 감성) | 렌더링 방식 | 드로우콜 / GPU 비용 |
|---|---|---|---|
| **Tier 1: 대기(Idle) — 전체·중거리** | 각 활성 부품의 3D 중심/상단에 **4각 별빛 글린트(Cross-Star Sparkle) + 미세한 동심원 리플 파동(Pulse Ring)**이 부품마다 엇갈린 박자로 잔잔하게 반짝임. (기존 원형 버튼 UI가 아니라 순수 3D 빛 입자/셰이더 표현) | 활성 부품 전체의 앵커를 **단 1개의 `THREE.Points`(또는 `InstancedMesh` 1개)**로 통합 렌더. 커스텀 프래그먼트 셰이더에서 4각 별빛 + 소프트 글로우 + 위상 맥동 계산. | **드로우콜 총 1회** (부품이 5개든 30개든 동일), **스텐실 클리어 0회** |
| **Tier 1-B (선택 옵션): 근거리 확대 시** | 카메라가 가까이 다가간 부품(화면 투영 크기 ≥ 32px, 화면 중앙 기준 **최대 3~4개** 제한)에만 **1패스 금속 광택 스윕(Sheen Sweep)**이 3.5~5초 주기로 사선으로 스쳐 지나감 ("샤라락~" 게임 아이템 반짝임). | 뒷면 스텐실 아웃라인 없이 **앞면 1패스 셰이더**(`depthTest: true, depthWrite: false, polygonOffset`). 스윕 band는 `fract(uTime * 0.25 + phase)`로 계산. | 근거리 상위 3~4개 부품만, 부품당 1패스(기존 대비 1/3 이하), **스텐실 0회** |
| **Tier 2: 선택됨(Selected, `menuPart`)** | 탭한 **부품 1개만** 선명하게 강조(타깃 락온 느낌). 주변 대기 반짝임은 일시적으로 밝기를 30%로 낮춰 시선을 선택 부품에 집중시킴. | **선택된 1개 부품에 한해** 기존 `PartGlow`의 림 + 윤곽선 + 상승 스파크 파티클(`part.root`)을 켠다. | **최대 1개 부품만** 풀 렌더 → 체감 부하 극소 |

#### 시각적 깔끔함(Clutter 방지) 필수 규칙 4가지
1. **화면 겹침 억제 (Screen-space Decluttering)**:
   - 전체 보기에서 기계실(7개 이상)·승장문(층당 4종)의 반짝임 점이 한곳에 뭉치면 지저분해진다.
   - 투영 좌표 기준 **서로 `36~44px` 이내에 겹치는 대기 비콘은 가장 대표성 높은 1개(또는 카메라 최단거리 1개)만 표시**하고, 줌인해서 간격이 벌어지면 세부 부품 비콘이 자연스럽게 나타난다.
2. **거리별 단계 노출 (Progressive Discovery)**:
   - **원거리(> 12m, 전체 보기)**: 핵심 대표 구역/대형 시연 부품(기계실 조속기·권상기·로프브레이크·제어반, 피트 완충기·사다리, 카/승장문 대표 지점 등 최대 6~8개)만 잔잔히 반짝여 "눌러 보고 싶은 랜드마크" 역할을 한다.
   - **중·근거리(≤ 10m, 줌인 또는 시점 메뉴 이동 후)**: 기존 각 모듈의 거리 게이팅(`3m~10m`)에 따라 인터록·연동로프·종단 스위치·비상키·조명 스위치 등 세부 부품이 모두 깨어난다.
3. **색상 팔레트 (사용자 금색 선호 반영)**:
   - **안 1 (단일 고급 골드 — 추천)**: 모든 대기 비콘을 따뜻한 샴페인 골드(`#ffcf5c` 코어 → `#fff6d6` 별빛 중심)로 통일해 고급스럽고 통일감 있는 게임 느낌을 준다. 선택 시 더 밝은 화이트골드(`#fff2c8`)로 강해진다.
   - **안 2 (미세 2톤 구분)**: 교육 시연 부품은 **샴페인 골드(`#ffcf5c`)**, 설비 조작 부품(조명·문·사다리·비상통화)은 **부드러운 민트 화이트(`#c8f0df`, 현재 모바일 운행 LED와 동일 계열)**로 구분해 기능을 직관적으로 암시한다.
4. **절전·접근성 연동**:
   - `IdleThrottle.pulseTime(now)`에 그대로 연결해 정지 화면 30→12fps에서도 끊기지 않게 맥동 속도를 늦춘다.
   - `prefers-reduced-motion: reduce`에서는 리플/스윕을 멈추고 은은한 고정 빛점만 표시한다.
   - 설정의 `부품 빛 효과`(`#part-glow-toggle`)를 끄면 Tier 1 대기 반짝임만 끄고, 3D 탭 및 Tier 2 선택 강조·팝업은 유지한다.

### 3-2. 영역 2 — 모바일 소형 팝업 실행 & 터치 충돌 해결

#### 소형 팝업 디자인 규격 (`#part-menu` 모바일 전용 리디자인)
- **목표**: 3D 부품을 가리지 않으면서, "무슨 부품인지 확인하고 → 눌러서 실행"하는 최소 크기 카드.
- **크기·타이포그래피 (기존 `#m-demo-preview` 212px보다 더 슬림하게)**:
  - 폭: `168~184px` (`max-width: calc(100vw - 24px)`), 패딩 `9px 10px`, 둥근 모서리 `13px`.
  - 스타일: 현재 모바일 HUD와 통일된 밝은 반투명 카드(`background: #f8fafdf5`, 얇은 골드 힌트 테두리 `1px solid #e6c97a`, 절제된 그림자).
  - 텍스트: 부품 이름 `12.5px` 볼드(1줄), 짧은 설명 또는 현재 상태 `10.5px` 회색(최대 1~2줄).
  - 액션 버튼: 높이 `38~40px`(단, 44px 터치 권장 기준을 지키려면 버튼 위아래 패딩/간격 확보 또는 `40px` 높이 + 가로 전체 폭 사용).
  - 닫기: 우상단 작은 `×` 버튼 + **선택된 3D 부품 재탭 시 팝업 닫기**(방금 구현한 시연 메뉴 재탭 닫기와 동일한 일관성) + 바깥 빈 영역 탭/드래그 시작 시 닫힘.
- **배치 규칙**:
  - 부품의 3D 경계상자 상단(또는 중심)에 맞춰 띄우되, 화면 상단 `#statusbar`, 하단 `#m-bar`, 좌우 `#m-run`/`#m-demo`와 겹치지 않도록 자동 반전·클램핑한다.
  - 카메라 드래그/핀치가 시작되면(`controls` `start` 이벤트) 팝업을 닫아 화면을 가리지 않게 한다. (정지 중 미세 떨림 방지를 위해 좌표는 `Math.round` 정수 픽셀 적용.)

#### 모든 부품의 2단계 실행 통일 (3단계 제거 & 오터치 차단)
| 부품 유형 | 기존 PC 동작 | 새 모바일 소형 팝업 구성 |
|---|---|---|
| **단일 시연** (조속기, ARD, 수동구출, 멀티빔, 종단 스위치, 주로프, 인터록, 연동로프, 이탈방지) | `#part-menu` → 항목 탭 즉시 실행 | `[부품명]` + 한 줄 설명 + **`[▶ 시연 재생]`** 버튼 |

#### 터치 제스처 & 더블탭 확대(`bindCameraFocus`) 충돌 해결
1. **모바일 탭 판정 통일 (`js/part-glow.js:432-448`)**:
   - `pointermove` 취소 임계값: PC `6px` 유지, 모바일 **`14px`**로 상향.
   - 멀티터치(`pointers.size > 1`) 감지 시 즉시 탭 취소(핀치 줌 해제 시 오탭 방지).
   - 비콘(Tier 1) 탭 히트 판정: 소형 부품 여유 반경을 모바일에서는 최소 **`22px`**(44px 직경 터치 타깃)로 확보하되, **가림 판정(`occluded`)**은 유지해 벽 너머 부품이 눌리지 않게 한다.
2. **더블탭 확대(`js/ui.js:1377-1454`)와의 공존 — 2가지 방안 비교**:
   - **추천안 — "빈 공간 더블탭 확대 유지 + 팝업 내 `[🔍 가까이]` 미니 버튼"**:
     - 부품이 화면에서 충분히 크면(≥ 22px) 1탭 → 소형 팝업 표시(지연 0ms, 즉각적인 게임 손맛!).
     - 팝업 헤더에 작은 `🔍` 버튼(해당 부품으로 `moveCam` 줌인)을 배치하고, 부품이 아닌 건물/벽/바닥 더블탭 확대는 기존대로 유지한다.
     - 부품이 원거리라 화면에서 너무 작으면(< 22px) 1탭 시 아예 팝업과 동시에(또는 팝업 대신) 해당 구역으로 부드럽게 접근하는 옵션도 선택 가능하다.
   - **대안 — "240ms 단일 탭 지연 판정"**:
     - 부품 위에서도 더블탭 확대를 유지할 수 있으나, 모든 탭마다 0.24초 반응 지연이 생겨 모바일 게임 특유의 경쾌한 반응감이 떨어진다.

### 3-3. 영역 3 — 시연 중 일시정지 & 언제든 첫 화면 정리 UX

#### 원안("일시정지 1번 → 정지, 1번 더 → 첫 화면 정리")의 핵심 UX 함정 분석
사용자 아이디어의 본질은 **"복잡하게 여러 버튼을 찾지 않고, 중간에 딱 멈췄다가 바로 첫 화면으로 깨끗이 빠져나오고 싶다"**는 것이다. 다만 **같은 버튼 하나를 2단 토글(`일시정지` → 재탭 시 `첫 화면 초기화`)로만 만들면 두 가지 치명적 문제가 생긴다**:
1. **계속 재생(`▶`) 불가**: 잠깐 멈춰 3D 부품을 돌려 본 뒤 이어서 시연을 계속 보고 싶을 때 돌아갈 방법이 없다.
2. **습관적 재탭 오초기화**: 유튜브·동영상 플레이어 습관 때문에 "일시정지 → 다시 재생"하려고 같은 버튼을 한 번 더 눌렀다가 시연이 통째로 날아가 첫 화면으로 돌아가 버린다.

#### 이를 해결하는 3가지 설계 대안 비교

| 대안 | 동작 방식 | 장점 | 단점 / 주의 |
|---|---|---|---|
| **추천안 A: 일시정지 시 2버튼 분리 (`❚❚ 일시정지` → `[▶ 계속]` + `[⌂ 첫 화면]`)** | 시연 중에는 깔끔하게 **`❚❚ 일시정지`** 버튼 1개(14종 시연 모두 통일)를 중심에 둔다. 1번 탭하면 시연이 멈추며(자유 3D 관찰 가능), 그 자리가 **`[▶ 계속 보기]`**와 **`[⌂ 첫 화면으로]`** 2개 버튼으로 전환된다. | - **2탭 리듬 유지**("일시정지 → 바로 첫 화면 정리")<br>- 습관적 재탭 오초기화 0%<br>- 계속 재생 + 3D 자유 관찰 완벽 보존<br>- 모바일 게임의 표준 Pause 메뉴 멘탈 모델과 일치 | - `BufferDemo`·`RetentionDemo`의 개별 정지 버튼 분기를 `DemoPause`로 일원화 필요 |
| **대안 B: 같은 자리 라벨 전환(`❚❚ 정지` → `⌂ 처음 화면`) + 옆에 작은 `▶ 재개`** | 1탭으로 정지하면 원래 버튼이 주황/붉은 **`⌂ 첫 화면으로`**로 바뀌고, 옆에 작은 `▶ 계속` 버튼이 뜬다. | - 사용자 원안("같은 자리 한 번 더 눌러 첫 화면")에 가장 가까움 | - 버튼 색·문구가 바뀌어도 습관적 더블탭으로 의도치 않게 초기화될 위험(최소 400ms 재탭 쿨다운 필수) |
| **대안 C: 1탭 정지/재개 + 길게 누르기(0.6초) 첫 화면** | 짧게 누르면 정지/재개, 0.6초 길게 누르면 첫 화면 복귀. | - 화면 버튼 수 최소 | - 현장 교육 직원(40~50명)이 길게 누르기 기능을 발견하기 매우 어려움 |

#### 기술적으로 반드시 함께 정리해야 할 3가지
1. **14종 시연 일시정지 UI 완전 통일**:
   - 현재 `js/demo-pause.js:99`는 완충기(`buffer-demo-pause`)와 문 이탈방지(`retention-demo-pause`)에서 `#demo-pause`를 숨기고 `js/mobile-demo-guide.js:148` 자막 우측에 정지 버튼을 따로 띄운다.
   - 모바일에서는 모든 시연이 **같은 위치의 공통 일시정지 → `[▶ 계속]` / `[⌂ 첫 화면]`**을 쓰도록 통일하고, 중복되는 하단 바 `시연 종료`·우상단 `×`의 관계를 단순화한다(우상단 `×`는 즉시 탈출용 비상구로 유지하거나 Pause 통합으로 정리 — 사용자 선택 필요).
2. **`window` 캡처 단계 이벤트 선점 필수**:
   - 각 시연(`ard-demo.js`, `ascent-demo.js`, `brake-demo.js`, `retention-demo.js`, `terminal-demo.js`, `rope-measure.js` 등)은 `document` 캡처 단계에서 허용 목록 밖 클릭을 `stopImmediatePropagation()`으로 차단한다.
   - 새 모바일 일시정지·첫 화면 정리 컨트롤은 `js/demo-exit.js:63-69` 및 `js/mobile-demo-guide.js:73-87`와 동일하게 **`window` 캡처 단계에서 먼저 받아 `DemoPause.toggle()` / `DemoExit.cancel()`을 호출**해야 14종 시연 전 구간(취객 이야기 HUD 숨김 구간 포함!)에서 누락 없이 동작한다.
3. **비-시연 상태(설비 직접 조작 후) "첫 화면 정리" 확장 제안**:
   - 시연 중에는 기존 `DemoExit.cancel()`이 페이지 리로드 없이 정상 착상·폐문·전체 보기를 완벽 복원한다.
   - 3D 부품 직접 탭이 열리면 사용자가 사다리 펼침·제어반/분전함 열림·비상키 개방·조명 변경·점검운전 등을 직접 조작할 빈도가 커진다. 이때도 페이지 리로드 없이 한 번에 원상복구 + 전체 보기로 돌아가는 경량 정리 함수(`resetSceneToHome()` — `HallManual.resetAll()`, 제어반/분전함 닫기, `PitLadder` 접기, 조명/카메라 복원, 필요 시 `setInspectionMode(false)`)를 `DemoExit` 옆에 두면 "언제든 원래 첫 화면으로 정리" 경험이 완성된다.

## 4. 기존 로드맵('모바일 장소별 조작 메뉴')과의 관계

`docs/ROADMAP.md`의 `2026-11-07 합의 — 모바일 장소별 조작 메뉴`는 모바일에서 3D 부품 탭이 잠겨 있었기 때문에 제안된 우회 경로였다. 이번 개편과 충돌하지 않고 **3축 보완 구조**로 정리할 수 있다.

1. **오른쪽 `시연` 메뉴 (유지)**: 강사·직원이 특정 사고/교육 시연을 이름과 설명으로 즉시 찾아 실행하는 빠른 목록.
2. **3D 부품 게임형 반짝임 + 소형 팝업 (이번 신규 중심)**: 사용자가 3D 승강기를 돌려보며 반짝이는 부품을 호기심으로 직접 눌러 탐색·실행하는 게임형 경험.
3. **시점 이동 연동 (보완)**: 하단 `시점` 메뉴로 기계실·카 상부·피트·승강장으로 이동하면, 그 구역의 세부 부품들이 근거리 Tier 1 반짝임으로 자동 깨어나 별도 거대 버튼 패널 없이도 바로 탭해서 조작할 수 있다. (아주 작은 스위치·조명만 필요 시 후속으로 장소별 퀵 버튼 보강.)

## 5. Claude Code 구현 전 사용자 확정 필요 항목 (5개)

Claude Code가 코딩을 시작하기 전에 아래 5가지만 사용자와 확정하면 재작업 없이 바로 착수할 수 있다.

1. **대기 반짝임 색상 톤**:
   - **(추천)** 전체 따뜻한 샴페인 골드 통일 (기존 푸른빛 반려 이력 준수)
   - vs 교육 시연(골드) / 설비 조작(민트 화이트) 미세 2톤 구분
2. **전체 보기(원거리)에서의 반짝임 범위**:
   - **(추천)** 원거리에서는 겹침 억제 + 대표 부품 6~8개만 잔잔히 반짝이고, 확대/시점 이동 시 세부 부품이 단계적으로 나타남
   - vs 거리 조건에 맞는 모든 부품을 바로 표시
3. **일시정지 → 첫 화면 정리 방식**:
   - **(추천 A)** `❚❚ 일시정지` 탭 → `[▶ 계속 보기]` + `[⌂ 첫 화면으로]` 2버튼 확장 (우상단 `×`는 즉시 탈출용 유지 또는 제거 선택)
   - vs **(대안 B)** 같은 버튼이 `⌂ 첫 화면으로`로 바뀌고 옆에 작은 `▶ 계속` 표시
4. **소형 팝업에 `🔍 가까이 보기` 버튼 포함 여부**:
   - **(추천)** 포함 (부품 위 단일 탭은 즉시 팝업, 확대는 팝업의 `🔍` 또는 빈 공간 더블탭)
   - vs 미포함 (240ms 지연으로 부품 위 더블탭 확대 유지)
5. **설비 직접 조작(사다리·제어반 문 등)의 "첫 화면 정리" 포함 여부**:
   - **(추천)** 1차는 시연 중 일시정지·첫 화면 정리에 집중하고, 2차에서 비-시연 설비 일괄 원상복구 버튼 추가

## 6. Claude Code 구현 권고 순서 & 검증 기준

### 6-1. 단계별 구현 순서 (점진적 검증 권장)
- **Phase 1 — 모바일 경량 게임형 반짝임 렌더러 (`js/part-glow.js` 분리/확장)**
  - `touchLocked()`를 전면 차단에서 **모바일 전용 모드 분기**로 전환.
  - Tier 1 단일 `THREE.Points` 별빛 글린트 + 리플 셰이더 + 화면 겹침 억제(36~44px) + `IdleThrottle`/`prefers-reduced-motion`/`#part-glow-toggle` 연동.
  - Tier 2 선택 부품(`menuPart`) 1개만 풀 퀄리티 발광.
  - **1차 검증**: 전체 보기·기계실·피트·승장 화면 캡처 + S22+ 동일 장면 드로우콜/FPS 전후 비교 (드로우콜 증가 +1~2회 이내 목표).
- **Phase 2 — 모바일 소형 팝업 & 2단계 실행 통일 (`js/part-glow.js`, `css/mobile-hud.css`, 필요 시 신규 `js/mobile-part-popup.js`)**
  - 모바일 터치 허용치 `14px` + 핀치 줌 차단 + 소형 부품 22px 터치 여유.
  - `isOperatingControl`도 모바일에서는 즉시 실행 대신 상태 배지 + 확인 버튼 팝업으로 통일.
  - 비교 시연(로프브레이크·주브레이크·완충기)은 소형 팝업 안에 조건 세그먼트 + `▶ 재생` 통합 (기존 `MobileHUD`의 `DEMO_CHOICES` 데이터 공유해 중복 하드코딩 금지).
  - 팝업 위치 클램핑 + 같은 부품 재탭 닫기 + 카메라 드래그 시 닫힘 + `🔍 가까이` 줌인.
  - **2차 검증**: 모바일 6종 해상도(320/360/390/600/844/740) 경계·겹침, PC 기존 클릭/호버 무회귀, 오른쪽 `#m-demo` 시연 메뉴 무회귀.
- **Phase 3 — 시연 일시정지 & 첫 화면 정리 통일 (`js/demo-pause.js`, `js/demo-exit.js`, `js/mobile-hud.js`, `js/mobile-demo-guide.js`)**
  - 14종 시연(완충기·문 이탈방지·취객 이야기 포함)의 일시정지 → `[▶ 계속]` / `[⌂ 첫 화면]` 경로를 `window` 캡처 기반으로 통일.
  - 일시정지 중 3D 자유 회전/확대 → 계속 보기 복원 / 첫 화면 즉시 복원 검증.
- **Phase 4 — 실기기(S22+ / 기준 기기) 터치 & 성능 검증**
  - 실제 터치로 오터치 없음(드래그·핀치 중 팝업 안 열림), 14종 시연 진입·일시정지·계속·첫 화면 정리, 설비 조작 2단계 확인, 동일 카메라·품질 조건의 전후 FPS/드로우콜/삼각형 측정.

### 6-2. 기존 테스트 계약 변경 주의 목록 (Claude Code 참고)
아래 기존 검증 도구는 **"모바일 단일 탭 무작동"** 또는 **과거 명칭**을 전제로 작성되어 있으므로 구현 시 의도된 계약 변경에 맞춰 함께 갱신해야 한다.
- `tools/verify_mobile_demo_menu.mjs` (L25-41): 현재 `// 2) 단일 탭 무작동`을 검증함 → **"단일 탭 시 시연은 즉시 시작되지 않고 소형 팝업만 열림"**으로 계약 갱신 필요.
- `tools/verify_part_glow.mjs` (L34, L39, L47-57, L70): 과거 명칭 `'조속기'`(현재 `'과속 조절기'`)와 모바일 즉시 실행(`ControlPanel.open`) 기대값이 남아 있음 → 모바일 2단계 소형 팝업 기대값으로 갱신 필요.
- `tools/verify_demo_presentation.mjs`, `tools/verify_demo_choices.mjs`, `tools/verify_demo_pause.mjs`, `tools/verify_demo_exit.mjs`: 회귀 테스트 필수 통과 대상.
