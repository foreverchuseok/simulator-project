# 수동 브레이크 개방·핸들 구출 시연

2026-10-02 사용자 요청. 동작 원본은 `js/manual-rescue-demo.js`이며 `index.html`에서 빌드·갱신한다.

- 벽에 걸린 개방레버와 핸들은 한 `PartGlow` 대상으로 묶는다. 기계실 근접 시점(10m 이내)에서 어느 공구를 눌러도 같은 「수동 구출 시연」 메뉴가 열린다. 정상 정지 상태에서는 층을 따로 호출하지 않아도 실행하며, 문이 열려 있으면 먼저 닫는다.
- 카가 이동하다 구조할 층보다 0.60m(`FAULT_GAP`) 아래에서 급정지한다. 충격음·380ms 화면 흔들림·승객의 관성 반응과 함께 화면을 어둡게 덮는 「쿵! · 운행 정지 / 정전입니다」 경고와 기존 정전 안내 음성(`snd.powerFailure`)을 낸다. 경고가 걷히면 층 바닥 기준선과 「↑ 60cm 미도달 · 레벨존 밖 · 문 잠김」 말풍선을 카 옆에 투영해 단차를 보여준다. 정상 자동운전과 ARD는 실행하지 않는다. 시연 중 운행 명령은 차단하며 ESTOP을 유지한다.
- 안전모를 쓴 동료는 `Mascot.createWorker()`로 기존 곰돌이의 메시·재질을 공유한다. 원래 승강곰은 개방레버를 맡고 동료는 핸들을 결합한다. 승객은 기존 `UCMDemo.character`를 사용하며 종료 시 원래 자세·표시 상태를 복구한다.
- 승강곰이 제어반을 열고 자동/수동 스위치를 전환하고, 제어반 상단의 빨간 비상정지(`EmergencyStopButton`)를 눌러 둔 뒤 분전함의 주전원 차단기를 내린다. 각 조작 직후 손을 몸쪽 아래로 빼서 바뀐 스위치 상태가 가리지 않게 한다. 이 세 시연 상태가 확인돼야 공구 결합과 수동 상승을 진행한다. 정상 운행 FSM의 전원 제어를 새로 구현한 것은 아니며 시연 내부 순서 조건이다.
- 작업자는 원래의 76% 크기다. 보행·계단 이동 없이 작업 위치로 장면을 전환(컷)하고 조작 대상 근접 시점으로 바로 넘어간다. 공구는 결합 위치에서 보여 주며 동료는 핸들 결합 장면부터 나타난다. 팔은 `Mascot.rescueRig()`의 길이가 고정된 두 관절로 움직인다. 발판은 손잡이 높이에서 계산하며 시연별로 재사용하고 종료 시 숨긴다. 착상 후에는 레버·핸들을 결합 위치에 둔 채 인터폰 앞으로 전환한다.
- 핸들 허브를 엔코더 앞 돌출축에 결합하고 확대 관찰한다. 결합 후에도 브레이크 개방 전에는 회전하지 않는다. 레버 포크는 금색 코일 양옆의 X축 핀에 결합한다. 승강곰은 코일 뒤편에서 브레이크를 바라보고 두 레버를 양손으로 자기 쪽으로 당긴다. 핸들 작업자는 엔코더 앞쪽을 유지한다.
- 수동·STOP·주전원 차단·브레이크 개방·핸들 결합 조건이 모두 참일 때만 7초(×1.65) 동안 0.60m 상승한다. 보행·공구 조작·설명 대기는 기존 대비 1.65배속이다. 카/균형추는 반대로 움직이며 기존 로프·시브·25:1 웜 연동을 공유한다. 핸들 피벗은 월드 Z축이고, 웜 회전각 변화와 일치한다. 기계적 수동 이동이므로 모터를 켜거나 FSM을 정상 자동운전으로 바꾸지 않는다.
- 레벨 일치 후 브레이크를 다시 체결한다. 승강곰은 실제 기계실 인터폰 수화기를 들고 통화하며 기계실/카 통화 표시등을 점등한다. 동료는 기존 `HallInspector` 긴 삼각키로 승장문을 해정한다. `CarDoor`의 같은 개방량을 승장문에 전달하여 두 문을 함께 열고 승객을 승강장으로 이동시킨다. 고장은 구출 완료 후에도 유지하며 「시연 종료 · 복귀」 또는 STOP/Escape로 정상 상태에 돌린다.
- 종료·중단은 소유한 GSAP 작업을 취소하고 카/균형추·공구의 벽걸이 위치·축 회전·카메라·도어 잠금·비상등·마스코트·수화기·비상정지 버튼 위치를 복구하며, 정전 경고·단차 말풍선·안내 음성을 끈다. 긴 키와 통화선 형상은 한 번 만들고 재사용한다.

## 모델 계약

- `blender/scripts/traction_machine.py` → `models/gltf/traction_machine.glb`: `tractionMachine.manualRescue`의 `shaftCenter`, `shaftRadius`, `shaftEndZ`, `releaseLug`, `releaseLugs`(좌·우 코일 옆 핀), `armIndex`, `releaseAngle`을 런타임이 읽는다. 엔코더 뒤 기존 축을 연장하고 핸들 보어 44mm에 맞춘 반경 21.5mm 돌출부를 만든다. 허브와 반경 간극은 0.5mm, 허브 두께 40mm와 축 길이 46mm의 차이는 6mm다. 기존 웜·브레이크 피벗 이름과 장착 치수는 유지한다.
- `blender/scripts/machine_room_accessories.py` → `machine_room_tools.glb`: `manualRescue`에 실제 형상에서 파생한 레버 포크 자리·손잡이, 핸들 허브·손잡이·보어·두께를 내보낸다. 양손 개방에 쓰는 두 번째 레버는 같은 GLB 메시·재질을 공유한다. JS에 공구 형상을 중복 생성하지 않는다.
- 같은 Python → `intercom_phone.glb`: 기존 전화기를 `IntercomPhone`, `IntercomHandset`, `IntercomCord`로 분리하고 수화기 중심·줄 끝점을 extras로 내보낸다. 통화 중 원래 거치 줄만 숨기고 기존 버퍼의 연결선을 갱신한다.
- `HallInspector.begin(floor, worker)`의 기본 작업자는 기존 `Mascot`이다. 수동 구출에서만 동료를 주입하므로 기존 피트 복귀·승장문 점검 흐름을 유지한다.
- `control_panel_sicon.py` → `control_panel.glb`의 `ManualModeSelector`는 `CabinetInterior` 아래 독립 피벗이다. `machine_room_power.py` → `elevator_distribution_box.glb`의 `MainBreakerToggle`은 로더에서 월드 위치를 보존하며 `BoxInterior`에 붙인다. 각각 Z/X축으로 조작하고 종료 시 원래 회전과 두 함의 개폐 상태를 복원한다. 같은 제어반 GLB의 `EmergencyStopButton`은 `CabinetBody` 아래 독립 피벗(버튼 머리 중심)이며 extras `pressDepth`(6mm×축 스케일 = 4.8mm)만큼 로컬 −Z로 눌린다. 함을 여닫는 도중에는 시연을 시작하지 않는다.

## 참고와 검증

- 사용자가 제공한 `temporary/otis-dual-brake-open.mp4`는 브레이크 개방 관찰 참고다. 핸들 결합 영상으로 취급하지 않는다.
- [제조사 W263 운전 설명서](https://www.liftequip.de/fileadmin/ELI_Dokumente/OM_Machine_W263C_EN.pdf), 비상운전 34~35쪽·엔코더 교체 45~46쪽의 브레이크 개방/핸드휠 관계와 엔코더 쪽 축 끝 구성을 참고했다. 현재 모형은 특정 오티스 제품 도면의 복제품이나 실제 하중 해석 모델이 아니다. 중력 이동 방향은 승객 수만으로 단정하지 않으며 이번 시연은 사용자가 요청한 수동 상승 구출이다.
- `node tools/verify_manual_rescue.mjs`, `--mobile`, `--mobile --narrow`: 3D 핸들 탭 메뉴, 고장/비착상, 브레이크 선행 개방, 축·각도 정렬, 카/균형추 연동, 착상, 통화·긴 키, 두 문 연동, 승객 탈출, 중간 중단·반복·문 열린 상태에서 실행/복귀를 확인한다. `--quick`은 전체 시연·복귀만 확인하고, `--fast`는 검증 시에만 GSAP 시간을 3배로 진행한다. 이동 후 60cm 정지, 정전 경고+음성 → 단차 말풍선 순서, 보행 없음, STOP 4mm 이상 눌림과 복귀, 두 작업자의 축소·방향, 양손 접촉과 양쪽 포크/핀 정렬도 검사한다. 캡처와 측정은 `.shot-manual-rescue/`이며 실제 모바일 기기 검증을 대신하지 않는다.
