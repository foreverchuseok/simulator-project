## 상승과속 시연 (2026-09-30)

- 원본 `js/ascent-demo.js`(`AscentDemo`). 기존 개문출발 옆 `#ascent-action` → 정상 작동/미설치 선택 → 상승과속 시연. 원래 위치를 저장하고 폐문 상태로 1층에서 시작한다. 승객은 기존 `Mascot` 승강곰 한 명이다. 시연 동안 점검 포즈 소유권을 사용하고, 종료 시 원래 부모·위치·크기·자세·표시 상태를 복원한다. 전망용 카 형상·재질은 유지한다. 참고 영상은 `temporary/overspeed-ascent/`의 두 파일이고 앱에 연결하지 않는다.
- 이중브레이크 고장 설명은 넣지 않는다. 큰 문구는 「웜기어 구동부 파손」이다. 원본 GLB의 웜·웜휠/출력축 파손 영역 삼각형만 시연용으로 분리하고 종료 시 원본 Geometry를 복원한다. 드럼/모터/브레이크 암은 보존한다. `traction.driveBroken` 동안 `spinTractionSheaves()`는 웜/드럼을 돌리지 않고 시브와 현수도르래만 실제 카 이동량으로 돌린다. 기존 기어비·피벗·GLB 파일은 변경하지 않는다.
- 흐름: 1층·폐문·승강곰 → 웜 파편·금속 충격 → 반대편 주 도르래/현수 도르래로 전환해 축 충격을 보여줌 → 약 5.5초 동안 놀란 곰과 카를 추적하며 3~4층 사이까지 상승 → 선택 정격의 1.3배에서 검출 → 주 화면 조속기 확대·진자 개방·역회전 접촉 → 스위치 상향 래치 전체를 슬로모션으로 확인 → 로프브레이크로 전환. 파손부터 급상승 시작까지 약 6.1초다. 접촉 위상은 GLB `mechanism.switchHitPhase`, 진자 개방량/스위치 각도는 GLB pose에서 읽는다. 하강용 `governorTrip()`·캐치슈·카 쐐기는 작동시키지 않는다. 조속기 로프는 잠그지 않는다.
- 후속 조정(2026-09-30): 상승 추적 재생은 위 최초 5.5초에서 30% 빠른 5.5/1.3초(약 4.23초)로 줄였다. 스위치 상향 래치는 수평 기준 +75°이며 GLB `switchUpRot`으로 기본 기울기를 보정한다. 하강 조속기도 −75°로 함께 변경했다. 상세는 `docs/GOVERNOR-DESIGN.md`의 상·하 래치 계약을 따른다.
- 상승 경로는 요청한 3~4층 추적 장면에 맞춰 가속과 시간 배율을 파생한 교육용 연출이다. 실제 사고의 검출 거리/가속을 예측하지 않는다. 스위치와 파지는 같은 사건을 순서대로 확대해서 보여주며, 카메라 전환·정지 후 곰 반응에는 교육용 시간 정지가 포함된다. 화면상의 대기 시간이 실제 제어 응답 지연을 뜻하지 않는다.
- 정상: 스위치 상향 타격을 보여준 뒤 상·하 턱을 75ms 동안 닫는다. 행정은 `UCMDemo.jawTravel`의 -13/+9mm를 공유한다. **실제 턱 접촉 후** 소리·먼지·화면 충격과 제동을 시작하고 추가 85mm에서 멈춘다. 턱 닫힘 동안 카/로프 이동도 유지한다. 카 정지 뒤 측면에서 곰이 0.28m 뜬 후 착지하고 다시 선다. 결과는 「로프브레이크 작동 · 무사 착지」다.
- 미설치: 설치 그룹을 숨기고 스위치가 작동해도 계속 상승한다. 카 정지 높이는 `현재 카Y + 현재 균형추Y + cwtBufferStrike.faceY - bufferGrp.userData.cwt.topY`에서 계산한다. 우레탄은 기존 60mm 행정을 압축하며, 유입식은 현재 모델의 상면에서 충돌한다(별도 유압 행정 해석 없음). 균형추 전체와 피트·완충기를 원경으로 잡고 큰 충돌음·먼지·충격파·화면 진동을 보인다. 이후 카로 전환해 곰이 천장 가까이 뜬 뒤 바닥에 떨어져 옆으로 쓰러지는 「큰 부상」 장면을 보여준다(잔혹 묘사 없음). 곰의 실제 경계로 바닥/천장 관통을 막는다. 가속·파지거리·반응은 교육용 연출이며 제품 성능/상해 판정값이 아니다.
- 종료: 상시 `종료 · 정상 복귀`, STOP, 결과의 고장 복귀, Escape, 점검 전체 리셋. 예약 콜백/파편/턱/승객 트윈을 모두 취소하고 카·균형추·시브 각도·웜·케이스 절개·이중브레이크 상태·턱·스위치·완충기·재질·카메라·FSM을 복원한다. 활성 중 기존 `overspeedActive` 잠금과 입력 차단으로 다른 시연/속도/도어/점검 명령과의 경합을 막는다.
- 검증: `node tools/verify_ascent.mjs` / `--mobile`(390px) / `--narrow`(320px). `--quick`은 두 모드·정지 버튼·복귀 후 운행만 확인한다. ## 배선 계약

- 조속기 스위치와 로프브레이크에서 바닥까지는 검은 외피 전선을 표시하고, 이후는 덕트 안으로 들어가 제어반 하단까지 이어진다.
- 덕트는 높이 22mm, 전체 폭 140mm의 경사진 단면이다. 덮개·접속판까지 포함한 최고점은 24mm다. 체대 외측과 전면을 돌아 분기한다.
- 로프브레이크 선은 측판과 가로 받침을 따라 내려온 뒤 체대 외측에서 바닥 덕트에 진입한다.
- 조속기 시작점은 `overspeed_governor.py`의 스위치 치수·기울기로 계산한 `BaseFrame.userData.mechanism.switchCableExit`다. GLB 로드 후 조속기 마운트의 회전·1.5배 스케일을 적용한다. JS에 스위치 위치를 따로 복사하지 않는다.
- 제어반은 `js/control-panel.js`(SICON-4000형 GLB, 축별 scale)이며 좌측벽 앞쪽 `CP_Z`(index.html)에 둔다. 개방 레버·수동 핸들(machine_room_tools.glb)은 벽 중간 Z −1.20·−1.42, 그 사이는 ARD·차단기함 자리다. 덕트는 제어반 받침 앞면(`panelFrontX`) 30mm 안쪽에서 나오고, 세로 간선 X는 `panelFrontX + 0.135`다.
- 권상기 분기: 제어반 → x=-0.77(체대 -X 바깥, 방진고무 판과 5mm)로 덕트를 뻗는다. 권상기 GLB의 `cableExits`에서 나온 이중브레이크·모터·엔코더 전선관 3가닥이 여기로 들어간다(`attachTractionMachine`, 계약은 [TRACTION-MACHINE.md](TRACTION-MACHINE.md)).
- 조속기 GLB 형상과 가동 노드는 유지하고 전선 연결점 메타데이터만 추가했다. 원본 수정 후 GLB 재내보내기가 필요하다.

## 개문발차(UCM) 시연 — 로프브레이크 작동

- 공개 화면 문구(2026-09-30 수정): 사용자 제공 `스크린샷 2026-09-30 073515.png`의 10.7.5·그림 20과 [국가법령정보센터 별표 22, 10.7.5](https://www.law.go.kr/LSW/flDownload.do?bylClsCd=200201&flNm=%5B%EB%B3%84%ED%91%9C+22%5D+%EC%97%98%EB%A6%AC%EB%B2%A0%EC%9D%B4%ED%84%B0+%EC%95%88%EC%A0%84%EA%B8%B0%EC%A4%80%28%EC%A0%9C4%EC%A1%B0%EC%A0%9C1%ED%98%B8+%EA%B4%80%EB%A0%A8%29&flSeq=141709087)를 대조했다. 정상 결과·미작동/미설치 안내는 `UCM_STOP_GUIDE`의 공용 문구를 사용한다. 상승 장면에 맞춰 가) 승강장 기준 1.2m 이하, 나) 승강장문 문턱~카 에이프런 최하단 수직거리 200mm 이하, 라) 카 문턱~승강장문 상인방 수직거리 1m 이상을 안내한다. 다)는 반-밀폐식 승강로 조건이며 이 장면의 안내에는 넣지 않는다.
- 기존 약 450mm·노출률 표시는 시뮬레이션 결과이고, 에이프런 2/3는 현장 설명과 현재 연출의 참고 비율이다. 이를 10.7.5의 기준값으로 표시하지 않는다. 화면에서는 거리 기준으로 교체하되 운동·턱 파지·정지 위치·효과는 유지했다. 현재 시연은 균형추보다 가벼운 빈 카의 상승 조건이다. 기준 자체는 무부하부터 정격하중 100%까지 적용되므로 이 한 장면으로 전하중 적합성을 판정하지 않는다.
- 동작 원본은 `js/ucm-demo.js`(`UCMDemo`), 문구·국소 먼지·세 장면 모아보기는 `js/ucm-effects.js`다. 로프브레이크 근접 아이콘에서 정상·미작동·미설치를 선택하고 재생한다. 시연 내내 보이는 「종료 · 정상 복귀」, 정지 버튼 또는 결과 화면의 기존 `RST`로 복귀한다. 효과음 `MACH.ucmBrakeFailure()`·`MACH.ropeBrakeBang()`·`MACH.bump()`는 `js/ui.js`에 있다.
- 흐름: 문 열림 → 승객 캐릭터 「퉁이」가 승장 문턱까지 걸어옴 → 한 발 내딛는 순간 권상기 브레이크가 풀리며 빈 카가 상승(가속 0.8m/s²) → 넘어짐 → 기계실 → 판정. 장면 전환은 시간이 아니라 사건(상승량·착지)으로 잇는다.
  - 승장(문턱 높이 카메라, 느린 동작 배율 0.65): 탑승 순간 큰 「브레이크 기능 상실」 문구와 권상기 주브레이크 고장 설명·묵직한 금속음·짧은 화면 충격을 보인다. 카 바닥이 0.015m 올라오면 승객이 놀라 내민 발을 뺀다(`startle`). 0.07m에서 문턱에 걸려 앞으로 넘어진다(`trip`). 허리를 굽혀 상체가 올라가는 카 바닥을 덮치고, 다리는 승장에 선 채 에이프런 면 바깥에 남는다(참고 영상 SBS 사례). 세로 화면은 거리를 늘리되 X 위치를 고정해 승장 난간을 피한다.
  - 넘어짐 계산: 굽힘각별로 "카 안쪽 정점의 최저 높이" 표(`buildLeanTable`)를 시연 시작 때 한 번 만든다. 매 프레임 카 바닥 높이에 맞는 최대 굽힘각을 고른다(`leanFor`, 보간 없음, 여유 6mm). 바닥이 올라오면 상체가 떠밀려 올라간다. 굽힘각이 0.35rad보다 작아져야 하면(미작동, 바닥 약 0.47m 이상) 몸 전체가 카 바닥에 실려 들린다.
  - 상체가 바닥에 닿으면(`onLanded`, "쿵") 배율 0.12로 0.45s 보여 준 뒤 0.65s 만에 기계실로 간다. 전환 상승량은 약 +0.24~0.25m로, 검출 높이 0.33m 전이다. 전환 중 배율은 0.03이다.
  - 기계실: 로프브레이크 옆·뒤 사선(`MR_VIEW`)이다. 정상은 배율 0.65, 미작동·미설치는 0.12다. 정상에서 검출 후 턱이 닫히는 75ms 동안 교육용 시간을 정지하고, **상·하 턱이 로프에 닿는 콜백에서** 제동·「팍! 로프 파지」·체결음·짧은 마찰음·국소 먼지·화면 충격을 시작한다. 먼지는 접촉면 양 끝에만 낮은 불투명도로 표시하며 턱 재질은 변경하지 않는다. 정지 뒤 1.2s 정적으로 제동 결과를 보여준다. 동작 줄이기 설정에서는 화면 흔들림·문구 확대를 생략한다.
  - 정상: 검출 0.33m → 정지 약 +0.45~0.47m(시뮬레이터 에이프런 0.75m의 2/3 이전). 승장으로 돌아와 몸을 일으키고 주저앉은 뒤(`recover`), 고장 발생·개문발차·로프 파지 당시의 실제 렌더 세 장면과 10.7.5의 상승 정지 기준을 보인다. 운동 수치는 교육용 모델의 결과이며 화면의 기준값과 구분한다.
  - 미작동·미설치: 로프가 계속 움직이고, 승장으로 돌아오면 승객이 카 바닥에 실려 들려 올라간다. 0.8m에서 붉은 "사망사고" 안내 카드로 전환한다(잔혹 묘사 없음).
- 턱 이동량 근거: `rope_brake.glb`의 `BrakeUpperJaw` 홈 바닥 +19mm, `BrakeLowerJaw` 면 −15mm, 로프 반지름 6mm. 다른 형태(비켜서 위에서 아래로 무는 구형)는 참고 영상의 과거 기종이며 사용하지 않는다.
- 복귀: 예약 콜백·승객/턱 애니메이션·화면 효과 취소 → 턱 해제 → 카를 원래 층 착상 위치로 서행 → 도어 닫힘 → 운행 가능. 개문 도중·카메라 전환·턱 접촉 직전·승객 회복 도중에도 복귀하며, 늦은 개문 완료 콜백이 시연을 다시 시작하지 못하게 한다. 카·균형추·턱·카메라 설정을 복원한다. 최상층, 점검운전, BYPASS, 다른 시연·고장 중, 사다리 펼침 상태에서는 시작하지 않는다.
- 에이프런 관통 방지: 넘어진 자세는 다리가 수직으로 에이프런 면 바깥에 남고, 카 안쪽 정점은 굽힘각 표로 항상 카 바닥 위에 둔다. 주저앉는 자세는 `clearZ()`가 정점을 실측해 위치를 정한다.
- 검증: `node tools/verify_ucm.mjs normal fail none`(Live Server 5500). 근접 아이콘·모드 선택·재생·종료를 실제 클릭/탭하고, 상체 착지 뒤 기계실 전환(상승 0.15m 이상, 검출 전)·상체-카 바닥 간극(0~15mm)·기계실 화면 파지·매 프레임 에이프런 관통량(0 이어야 함)·턱 접촉과 효과음 동기·정지 높이·세 장면·사망 카드·복귀 착상·이후 정상 운행·콘솔 오류를 확인한다. `UCM_WIDTH=390` 또는 `320`으로 터치 에뮬레이션하며 `.shot-ucm[-폭]/`에 화면과 보고서를 남긴다.
- 중단·반복 검증: `node tools/verify_ucm_recovery.mjs`. 개문·놀람·카메라 전환·접촉 직전·승객 회복 도중 취소, 카/균형추/카메라/턱 복원, 지연 효과음·자세 변경 없음, 동작 줄이기와 정지 버튼 복귀를 검사한다. 실제 모바일 기기 조작·스피커 청취·성능은 별도 확인 대상이다.
