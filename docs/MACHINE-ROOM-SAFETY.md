# 기계실 로프브레이크·배선

## 형상과 장착 계약

- `js/environment.js`의 `buildMachineRoom()`에서 `js/machine-room-safety.js`를 호출한다. 별도 라이브러리나 운행 상태는 추가하지 않는다.
- 브레이크 기준점은 주 도르래와 현수 도르래의 상부 공통 접선 55% 지점이다. 기존 도르래 위치·로프 경로·브레이크 피치는 유지한다.
- 본체 원본은 `blender/scripts/rope_brake.py`이며 `models/gltf/rope_brake.glb`로 내보낸다. 로더가 기존 `RopeBrake` 그룹 안에 `RopeBrakeModel`을 붙인다. 설치 받침과 배선은 JS에 유지한다.
- 사진 075811·075803·075936·080035를 참고해 노란 절곡 덮개, 주조 금속 턱과 양각 `Safe-Tech / Rope brake`, 도금 가이드 봉·너트·체결 확인선, 양쪽 검은 수동 손잡이와 덮개 옆에 고정한 절곡 해제 레버를 만들었다. 경고·상호 표기도 GLB 안에 포함한다. 제품 치수 도면을 복제한 모델은 아니다.
- 아래 접촉판은 평면이며 위 접촉판은 실제 홈 5개를 갖는다. Python이 `buildWireRopes()`의 가닥 수·X 간격·반지름을 읽어 홈 중심을 맞춘다. 홈 반경 8mm·깊이 4mm, 기존 로프 반경은 6mm다.
- 주물 미세 요철은 GLB에 포함한 128×128 노멀 맵으로 표현한다. 턱·덮개·가이드 부품·손잡이·표기를 의미별로 묶어 내보낸다.
- 지지는 `체대 양쪽 채널 → 받침 슈·볼트 → 가로 받침 2개 → 발판 → 양쪽 측판 → 본체 체결부`로 이어진다. 브레이크를 체대에 직접 용접하는 형상은 없다.
- 받침 슈는 체대 상면과 기존 현수 도르래 판 상면의 높이 차에서 파생한다. 측판 상단은 기울어진 본체 체결점에서 역산하므로 본체 아래에 떠 있는 기둥을 두지 않는다.
- 본체 로컬 Y=0이 로프 중심이며 턱 사이 간극은 30mm다. `RopeBrake` 이름을 유지한다. 실제 제동 하중 계산·제품 인증을 나타내는 모델은 아니며 현재 브레이크의 별도 작동 애니메이션은 없다.
- `ROPE_BRAKE_MOUNT`가 턱 간극·체결점·전선 연결점의 공용 JSON 원본이다. Python이 읽고 GLB extras에 저장하며 로더가 일치 여부를 확인한다. `RopeBrakeInstallation.userData.ready`가 GLB 장착 완료를 표시한다.

## 배선 계약

- 조속기 스위치와 로프브레이크에서 바닥까지는 검은 외피 전선을 표시하고, 이후는 덕트 안으로 들어가 제어반 하단까지 이어진다.
- 덕트는 높이 22mm, 전체 폭 140mm의 경사진 단면이다. 덮개·접속판까지 포함한 최고점은 24mm다. 체대 외측과 전면을 돌아 분기한다.
- 로프브레이크 선은 측판과 가로 받침을 따라 내려온 뒤 체대 외측에서 바닥 덕트에 진입한다.
- 조속기 시작점은 `overspeed_governor.py`의 스위치 치수·기울기로 계산한 `BaseFrame.userData.mechanism.switchCableExit`다. GLB 로드 후 조속기 마운트의 회전·1.5배 스케일을 적용한다. JS에 스위치 위치를 따로 복사하지 않는다.
- 권상기 분기: 제어반 → x=-0.77(체대 -X 바깥, 방진고무 판과 5mm)로 덕트를 뻗는다. 권상기 GLB의 `cableExits`에서 나온 이중브레이크·모터·엔코더 전선관 3가닥이 여기로 들어간다(`attachTractionMachine`, 계약은 [TRACTION-MACHINE.md](TRACTION-MACHINE.md)).
- 조속기 GLB 형상과 가동 노드는 유지하고 전선 연결점 메타데이터만 추가했다. 원본 수정 후 GLB 재내보내기가 필요하다.

## 확인

- `node tools/verify_machine_room_safety.mjs`: Live Server 캐시 비활성화, 접선 정렬, 받침 접촉, 전선 연결점, 기계실 전체·브레이크 양쪽·조속기 배선 화면.
- 같은 검증에서 GLB 로딩을 기다린 뒤 로프 5가닥 × 길이 방향 3곳에 광선을 쏴 홈·평면·하부 턱의 실제 표면 위치를 확인한다. 상부 홈 중심 Y=19mm, 홈 사이 평면 Y=15mm, 하부 접촉면 Y=-15mm다. 본체 단독 상부·하부 확대 화면도 저장한다.
- `node tools/verify_overspeed.mjs --shadows`: 조속기 트립·복귀·구출 운전 회귀 확인.
- `node tools/verify_rope_performance.mjs machine-safety-after`: 같은 PC·시점·품질에서 변경 전후 각 3회 비교. 실제 휴대폰·태블릿 조작과 성능은 별도 확인 대상이다.

## 개문발차(UCM) 시연 — 로프브레이크 작동

- 원본은 `js/ucm-demo.js`(`UCMDemo`)다. 고장 메뉴의 `UCM` 버튼과 `로프브레이크` 선택(정상·미작동·미설치)으로 시작하고, 같은 버튼(`RST`)으로 복귀한다. 효과음 `MACH.ropeBrakeBang()`·`MACH.bump()`는 `js/ui.js`에 있다.
- 흐름: 문 열림 → 승객 캐릭터 「퉁이」가 승장 문턱까지 걸어옴 → 한 발 내딛는 순간 권상기 브레이크가 풀리며 빈 카가 상승(가속 0.8m/s²) → 기계실 → 판정.
  - 승장(문턱 높이 카메라 `sillCam`, 느린 동작 배율 0.35): 카가 약 +0.13m까지 **눈에 보이게** 올라가 카 문턱 밑으로 에이프런 띠가 드러난다. 내민 발 밑으로 카 바닥이 0.015m 올라오면 승객이 놀라 발을 뺀다(`startle`, 시간이 아니라 상승량으로 발동).
  - 기계실로 이동하는 동안에는 배율 0.05로 거의 멈추고, 도착하면 배율 0.2로 로프 꼬임 무늬가 천천히 흐르다 파지된다. 파지는 반드시 기계실 화면에서 일어난다.
  - 기계실 시점은 로프 진입 방향 정면(브레이크 로컬 `MR_VIEW`)이다. 열림에서는 윗턱이 노란 덮개 안에 숨어 있다가, 파지 순간 황동 윗턱 판이 덮개 아래로 내려와 로프 5가닥을 누른다(0.12s). 턱이 주황으로 번쩍하고 화면이 흔들리며, 정지 뒤 2.2s 동안 멈춘 로프를 보여준다.
  - 정상: 상승 0.28m에서 검출 → 0.04s 뒤 턱이 로프를 문다(상부 −13mm·하부 +9mm, 0.05s), 감속 3m/s². 카는 약 +0.39m(에이프런 0.75m의 약 52%, 2/3 이전)에서 에러 정지한다. 승객은 에이프런에 발끝이 걸려 엉덩방아를 찧는다(경상).
  - 미작동: 턱이 움직이지 않는다. 미설치: `RopeBrakeInstallation`을 숨긴다. 두 경우 모두 카가 계속 올라가며, 사고 순간 전에 붉은 "사망사고" 안내 카드로 전환한다(잔혹 묘사 없음, 초등학생 시청 고려).
- 턱 이동량 근거: `rope_brake.glb`의 `BrakeUpperJaw` 홈 바닥 +19mm, `BrakeLowerJaw` 면 −15mm, 로프 반지름 6mm. 다른 형태(비켜서 위에서 아래로 무는 구형)는 참고 영상의 과거 기종이며 사용하지 않는다.
- 복귀: 턱 해제 → 카를 원래 층 착상 위치로 서행 → 도어 닫힘 → 운행 가능. 최상층, 점검운전, BYPASS, 다른 고장 중, 사다리 펼침 상태에서는 시작하지 않는다.
- 에이프런 관통 방지: 카가 출발하는 순간 내딛던 발을 거둬들인다. 부딪힘·엉덩방아·쏠림 자세의 위치는 `clearZ()`가 자세 정점을 실측해 에이프런 면(`CAR_FRONT_Z`) 바깥으로 정한다.
- 검증: `node tools/verify_ucm.mjs normal fail none`(Live Server 5500). 승장 화면 상승량(≥0.08m, 파지 전)·기계실 화면 파지·매 프레임 에이프런 관통량(0 이어야 함)·정지 높이·턱 파지·발끝 접촉(3mm)·사망 카드·로프브레이크 숨김·복귀 착상·이후 정상 운행과 콘솔 오류 0건을 확인하고, `.shot-ucm/`에 단계별 화면을 남긴다. 실제 모바일 조작·성능은 별도 확인 대상이다.
