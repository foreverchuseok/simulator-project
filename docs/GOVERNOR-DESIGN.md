# 조속기 형상과 작동점

## 2026-09-26 순차 과속 시연

`device_china.mp4`의 24~43초 조속기→하부 안전기 장면 전환과 사용자 요청을 참고했다.

- 3층 이상에서만 시작한다. 승강로 측면 구도가 잡힌 뒤 주로프 카측 5본이 끊어지고, 연결된 조속기 로프와 카의 낙하를 보여준다. 이어 기계실 확대→진자 개방·전기 차단→쐐기 결착→캐치슈의 뒤쪽 로프 파지→하부 링크 당김→안전기 확대·레일 파지 순서다.
- 분할 화면과 두 번째 렌더 패스를 삭제했다. 카메라 이동 중에는 다음 작동을 기다리며, 로프 파지는 0.85초 보여준 뒤 하부 장면으로 전환한다. 화면의 ‘느린 동작’은 교육용 시간 연출이며 실제 중력 가속도·제동 거리 계산 모델이 아니다.
- `js/ui.js`가 카메라·단계·효과음을 관리한다. 주로프 원본 카측 메시만 잠시 숨기고 재사용 가능한 끊어진 끝 메시를 표시한다. `js/elevator.js`의 `refreshRopes()`가 파단 끝을 카 위치에 맞춘다. 조속기 로프, 캐치슈 파지점, 고정된 클램프에 대한 카/링크 상대 운동은 기존 계약을 유지한다.
- 파단·쐐기 결착·캐치슈 파지·레일 파지에 서로 다른 합성 금속음을 사용한다. 불꽃은 쐐기 상승 90% 이후 레일 접촉 위치에 0.55초만 표시하며 작은 카메라 진동을 더한다. 주로프 조각과 불꽃 버퍼는 반복 시연 때 재사용한다. RST는 원래 로프 표시·카 외장·카메라·접점을 복원하고 기존 구출 운전을 실행한다.
- `node tools/verify_overspeed.mjs --shadows`, `--shadows --mobile`: 3층 미만 차단, 단일 화면의 단계 순서, 주로프 파단·조속기 로프 유지, 효과음 4회 순서, 불꽃 시점, 클램프/휠 정지와 링크 상승, RST·구출을 확인한다. 390×844는 터치 에뮬레이션이며 실기기 검증은 아니다. 화면은 `.shot-ovs/`, `.shot-ovs-mobile/`에 저장한다.
- 같은 PC Chromium·1280×850·DPR 1·같은 조속기/안전기 시점에서 전후 각 3회 측정: 두 시점 모두 프레임 중앙값 16.7→16.7ms, p95 16.7~16.8ms. 실측 파일은 `temporary/ovs-cinema-performance.json`이다. 실제 모바일 성능과 스피커 청취는 별도 확인이 남아 있다.

## 2026-09-26 스위치 타격 정렬

- 175622·1756221 표시 사진과 후속 설명 반영. 스위치 암을 진자 네모 뭉치와 같은 Z=0.034m 평면으로 옮겼다. 정상 회전 접촉을 막기 위해 스위치 전체를 X 방향으로 6mm 바깥으로 옮겼으며 타격 위상은 새 끝점에서 다시 계산한다. 수치는 GLB 모델 기준이며 화면 마운트 배율은 1.5다.
- 쐐기와 연동되는 캐치 좌단이 내려오면서 스위치의 가로축 원형 끝을 누른다. 좌단 접촉면·앞쪽 원형 끝의 깊이를 맞추고, 휠 쪽 끝은 림과 간섭하지 않도록 짧게 했다. 캐치·휠·쐐기의 기존 피벗과 로프 파지 위치는 유지한다.
- 진자 타격으로 먼저 전기 접점이 열리고, 이어 캐치 하강에 맞춰 스위치가 더 돌아간다. 접촉점·반경·최종 각도는 Python에서 GLB mechanism으로 전달하며 JavaScript는 원형 접촉 조건으로 회전각을 계산한다. 복귀 전까지 래치를 유지한다.
- `node tools/verify_governor_switch_contact.mjs`: 내보낸 메시로 정상 360도 회전 간극, 과속 타격, 캐치 하강 접촉을 검사한다. 정상 뭉치 중심의 최소 거리 7.805mm(뭉치 외접반경 6.223mm), 과속 거리 3.751mm(뭉치 반두께 4.4mm), 하강 접촉 오차 최대 0.035mm. 화면은 `.shot-governor-switch/`에 저장한다.
- Blender 내보내기와 과속→전기 차단→쐐기→로프 파지→정지·RST·구출 검증 통과, 브라우저 오류 0건. 동일 PC Chromium 1280×850·DPR 1·조속기 확대 시점에서 전후 각 3회 프레임 중앙값 16.7→16.7ms, 렌더 호출 494→494, 삼각형 235402→235574. 실제 모바일 조작·성능은 미검증이다.

## 2026-09-21 형상 보완

`device_china.mp4` 31~36초와 사용자 설명 영상 150806을 참고했다. 설명의 마지막 지시대로 기존 조속기 기본 구조를 유지하면서 투박한 부품을 다듬었다.

- 스위치: 24×102×18mm 케이스, 1.8mm 절곡 커버, 작은 체결 나사와 3.5mm 두께 액추에이터. 스위치 타격 끝점과 회전축은 기존 값이다.
- 쐐기: 기존 톱니에 맞물리는 끝점은 유지하고 피벗 뒤쪽 윤곽을 둥글게 정리했다. 축 칼라·육각 머리·홈을 더하고 가공 모서리를 보완했다.
- 진자: 두꺼운 연결 덩어리를 좁혀 원통 추와 연결부를 구별했다. 원통 모서리와 단면·체결부를 가공 금속처럼 표현했다. 질량·관성 계산 모델을 변경한 것은 아니다.
- 캐치 레버: 얇은 판과 완만한 하단 윤곽, 좌단 갈고리 모양을 보완했다. 일체형 캐치슈와 기존 스프링·피벗 연결은 유지한다.
- 금속 반사: `getGovernorMetalEnvironment()`가 작은 반사 환경을 한 번 생성해 조속기 불투명 금속 재질에만 적용한다. 배경·다른 부품의 조명은 바꾸지 않는다.
- 로프: 도르래 감김 구간 `TubeGeometry`의 길이 방향 UV를 직선 로프와 맞췄다. 6연선 요철과 56mm 꼬임 피치를 표현한다. 직선 경로·로프 직경·카 연결점·프레임별 갱신 흐름은 유지한다.

## 원본과 장착

형상 원본은 `blender/scripts/overspeed_governor.py`, 최종 파일은 `models/gltf/overspeed_governor.glb`다. 변경 후 Blender로 재내보내야 반영된다.

`js/environment.js`의 로더가 기존 이름·피벗으로 부품을 붙이고, `js/elevator.js`가 트립·복귀를 구동한다. 이번 작업에서 FSM·각도·타격 위상·작동 순서는 바꾸지 않았다. `BaseFrame`의 `mechanism` extras가 타격점·작동 자세·스위치 전선 출구를 전달한다.

전기 스위치는 현재 진자 타격 뭉치가 액추에이터 끝을 치는 구조다. 원본 영상의 외형을 참고했다고 해서 다른 제품의 모든 내부 작동을 그대로 복제한 모델로 해석하지 않는다.

## 검증

- `node tools/verify_governor_design.mjs before` / `after`: Live Server 캐시 비활성화, 전면·사선·스위치 확대, 전후 회전축·타격점·작동 각도 비교. 비교할 때 먼저 변경 전 `before` 기록이 있어야 한다.
- `node tools/verify_overspeed.mjs --shadows --detail-view`: 과속 시연·스위치·쐐기·로프 파지·RST·구출 운전.
- `node tools/verify_rope_performance.mjs governor-refinement-before` / `after`: 같은 PC·해상도·기본 시점·품질에서 각 3회 측정.
- 실제 휴대폰·태블릿 조작과 사용자가 느끼는 설명 가독성은 별도 확인 대상이다.
