# 카 도어 오퍼레이터와 승장문 연동

2026-09-19 사용자 요청. 배경은 다른 터미널에서 별도 작업하며, 이 구현은 배경 코드를 수정하지 않는다.

## 원본과 구현 범위

- `부품설계.pdf` 실제 PDF 228–237페이지: 카 헤더/픽싱 브라켓, 모터/벨트/텐셔너, 행거/문짝/가이드슈, CDL 클러치/카도어락, 게이트 스위치, OLS/CLS, SE600M 멀티빔, 해제 와이어.
- 현장 외형: 사용자 영상 `temporary/car-door/source.mp4` (엘박사 카도어 점검). 도금 판금, 중앙 게이트 스위치, 베인, 장공/체결부, 릴리즈 레버와 배선을 참고한다.
- 원리 교차 확인: [도어 커플링 특허 US3605952A](https://patents.google.com/patent/US3605952A/en), [카 도어 인터록 특허 US20210380373A1](https://patents.google.com/patent/US20210380373A1/en). 특정 특허의 형상을 그대로 복제한 모델은 아니다.
- `js/car-door.js`가 문짝·카도어락·클러치 운동학의 원본이며, 모터·벨트·로프 구동부는 `js/car-door-transmission.js`가 담당한다. 기존 앱의 `M.*` 재질과 고정 부품 병합 함수를 사용한다. 아카이브 코드는 로드하지 않는다.
- 도면에 없는 전체 부품 크기·링크 길이·캠 회전량은 현재 카/승장문에 맞춘 시뮬레이터 재구성이다. 도면상 설치 간극과 이 재구성 수치를 구분한다. 제조 도면의 완전한 치수 복제나 접촉력·마찰·탄성 해석 모델이 아니다.

## 좌표·형상 계약

- `CarDoor.dimensions()`가 카/승장문의 닫힘 중심과 행정을 공유한다. `cx=0.391`, `ox=1.145`, 한쪽 행정은 0.754m. `const S`는 변경하지 않는다.
- 카문은 `carGrp` 자식이며 카 그룹 위치, 로프·균형추 연동은 유지한다. 카문 중앙 간격은 3.5mm, 실 상면과 하단은 5mm다. 문 안쪽과 기존 입구 주의 외측 간격은 5mm다.
- 카 실의 폭은 완전 개방 문짝에서 역산한 3.092m다. 가이드슈가 개방 중에도 실 홈 안에 남는다. 홈 중심은 `doorZ`를 공유하며 기존 카/승장 실 수평 간극 30mm와 바닥 높이를 유지한다.
- 헤더 폭 2.84m는 최대 행거 이동 범위에서 역산한다. 행거 주행 롤러는 트랙 상면에 접하고, 하부 편심 롤러는 트랙 하단과 0.5mm 떨어진다.
- 모터는 카에만 있다. 카 상부 도어 컨트롤러는 기존 `carTopBox`와 별개이며 모터선/전원선을 표시한다. 멀티빔 어댑터는 기존 카 탑 박스 안에 추가한다.
- CDL 고정 캠 기준 102.6mm, 초기 캠 간격 6mm, 카도어락의 수평 여유 23mm를 표시한다. 기존 현장 승장 인터록의 롤러 배치에 맞춰 접촉 슈를 재구성했다. 해당 롤러의 위치/외경은 GLB 메시에서 읽으며 별도 하드코딩하지 않는다.
- 2026-09-20 실사 구동 방식으로 변경하면서 도면 232쪽의 긴 구동 링크 2개와 고정 브라켓을 제거했다. 짧은 베인 링크는 기존 평행 링크를 유지하며 수직 블레이드와 카도어락은 이번 교체 범위에서 보존한다. 가동부 피벗을 정적 부품과 합치지 않는다.
- `carDoorHardware_*` 메시의 `userData.sourceRanges`에 합쳐진 판금·볼트 이름을 보존한다. 센서, 접촉 슈, 움직이는 캠·후크·스프링은 별도 참조다.

## 동작 계약

### 실사 모터·벨트·연동로프 (2026-09-20).

- 기준은 사용자 실사 `20260909_112451.jpg`, `20260909_112453.jpg`와 `화면 녹화 중 2026-09-20 104127.mp4` 설명이다. 카도어락은 기존 도면 기준을 유지하며, 구동 방식만 교체한다.
- 올라온 취부판 앞의 큰 풀리와 동축 로프 드럼, 작은 모터 풀리, 검은 구동벨트, 아래쪽 안내 풀리, 좌우 연동로프와 문짝 취부 클램프로 구성한다. 모터와 컨트롤 박스는 취부판 뒤에 두고 기존 카 탑 박스로 배선한다.
- 원본 수치는 `CarDoorTransmission.spec`에 모은다. 큰 풀리 반경 180mm, 모터 풀리 45mm, 로프 드럼 65mm, 안내 풀리 50mm다. 사진에서 확인되지 않는 치수·로프 안내 홈·클램프 취부는 기존 헤더와 행정에 맞춘 재구성이며 실물 제조 치수로 해석하지 않는다.
- 구동량은 기존 문 변위 + 해정 유격 14mm다. 드럼 회전각은 구동량/드럼 반경, 모터 회전각은 큰 풀리 회전각의 4배, 안내·끝 풀리는 각 반경에 따른 회전량을 사용한다. 클램프 슬라이더와 스프링이 해정 유격을 표현한다. 카문·승장문 FSM은 유지한다.
- 벨트의 직선부는 두 피치원의 외접선으로 연결한다. 로프는 동축 드럼에 감긴 뒤 안내 풀리의 분리된 두 홈과 양끝 풀리를 경유한다. 수평 복귀 가닥은 안내 풀리 원판 뒤로 지나가도록 깊이를 분리한다. 개폐 중 Geometry를 다시 만들지 않으며 회전 표시와 로프 이동 표시는 동일 구동량을 따른다.
- `verify_car_transmission.mjs`는 101개 자세에서 회전비·클램프 좌우 이동·끝 간극·로프 형상 재사용, 안내 풀리 원판 관통 부재, 긴 링크 제거를 확인한다. `.shot-car-transmission/`에 정면·사선·후면 모터·개방 렌더와 JSON을 남긴다.

### 승장문 독립 점검 개방 (2026-09-20).

- `js/hall-manual.js`의 `HallManual`이 층 선택·삼각키·개방량·관찰 위치를 담당한다. 고장 메뉴의 **문 점검**에서 대상 층 → 삼각키 해제 → 완전 열기 또는 개방량 조절 → 승장문 BYPASS → INS ▲/▼ 홀드 순서로 사용한다. 화면 삼각키도 같은 기능으로 연결한다.
- 층별 `manualActive`·`manualOpen`은 카문 구동과 별개다. 카문이 닫혀 있고 카가 정지한 상태에서만 조작하며, 다른 층 선택이나 카 접근·통과로 열린 문을 닫지 않는다. 독립 개방은 기존 `CarDoor.dimensions().stroke`와 `spinDoorDrive()`를 사용한다.
- 수동 개방 중에는 정상 카문 개폐를 막고, `CarDoor.pose()`가 해당 층 문 위치를 덮어쓰지 않는다. 아래 정상 개폐 계약의 단일 구동 규칙은 수동 점검 상태를 제외한 정상 운행에 적용한다.
- 승장문 닫힘·잠금은 자동 출발, 바이패스 없는 점검 출발/이동, AUT 복귀 및 구출 운전에 확인한다. 승장문 BYPASS는 기존 카문 닫힘·잠금 감시를 유지한다.
- 관찰 위치는 선택 층에 고정하며 세로 화면의 가로 시야를 고려한다. 사용자가 카메라를 자유롭게 조작하거나 패널을 접을 수 있다. 카 움직임에 따른 자동 추종은 하지 않는다.
- 복귀는 닫기 → 삼각키 재잠금 → BYPASS 해제 → AUT 순서다. 열린 상태의 재잠금은 거절한다. 여러 층을 열었다면 모두 닫고 재잠금해야 한다.
- `node tools/verify_hall_manual.mjs`: 40%/100% 개방 양방향 통과, 카문·다른 층 유지, 카메라 유지, 출발 차단, 카문 이상·포커스 상실·비상정지, 정상 도어·운행 복귀, 터치 홀드 해제를 검사한다. PC PNG·터치 에뮬레이션 PNG·JSON은 `.shot-hall-manual/`에 기록한다. 실제 모바일 검증은 별도다.

1. 정상 개방은 카가 현재 층 정위치 ±5mm 안에 있고 승장 GLB와 카도어 조립이 준비된 경우에만 허용한다. 이 값은 시뮬레이터 정상착상 판정이며 실제 제품의 해제구간 규격을 의미하지 않는다.
2. 첫 0.24초에 구동계의 해정 유격을 취하고 베인을 접촉시킨 뒤 승장 후크와 카도어락을 해정한다. 접촉 전에는 승장 후크가 움직이지 않는다. 삼각키로 이미 해정된 승장 후크는 그 상태를 유지한다.
3. 다음 1.15초에 카 우측 문 위치 하나를 구동한다. 반대 카문과 **물린 층만** 같은 거리로 움직이며 `spinDoorDrive(h)`가 승장 연동로프·풀리·폐문 스프링을 즉시 갱신한다. 승장문 독립 GSAP 트윈은 사용하지 않는다.
4. 닫힘은 0.95초 문짝 복귀 → 0.24초 베인 이탈·재잠금 순서다. 닫힘 완료 후에만 `IDLE` 및 운행 콜백을 내보낸다. 열림 완료 전에는 `DOOR_OPENING`을 유지한다.
5. `CarDoor.secured()`는 조립 준비·구동 정지·카도어락·게이트 접점·CLS를 함께 확인한다. 자동/점검 운전 출발에 사용한다. 게이트 접점은 두 문 사이 간격 7mm에서 붙고 OLS/CLS는 문 위치를 따른다.
6. 비상정지는 진행 중인 도어 타임라인도 일시정지한다. 복귀 시 해당 개폐 단계를 이어간다. 닫힘 중 들어온 후속 운행 콜백은 재잠금 뒤 처리한다.

운동학은 단일 입력에서 위치와 접촉을 계산하는 방식이다. 실제 모터 제어 보드/커넥터 로직, 안전회로 전체, 물체 검출/멀티빔 재개방은 이번 범위에 포함하지 않는다. 해제 와이어·릴리즈 레버는 형상과 연동 표시이며 별도 수동 당김 UI는 없다.

## 검증

- 2026-09-19 배선 정리: 도어 제어반 공급선을 천장 전면 가장자리→좌측 레인→카탑 박스 하단 공용 인입구로 연결하고 모터선은 헤더 뒤쪽의 직각 경로로 정리했다. `batchHardware()`에서 인스턴스 메시를 제외하여 배선 고정대가 실내의 큰 상자로 병합되는 오류를 수정했다. 상세는 [CAR-CONTROLS.md](CAR-CONTROLS.md)의 최신 배선 계약이다. 도어 기구와 가동 문짝의 여유선은 유지한다.

- 2026-09-19 후속: Live Server 캐시 비활성화 검증 통과. 해정/이동 각 101자세와 간극·접촉·운행·터치 에뮬레이션에 더해, 닫힘 중 비상정지·복귀 및 대기 중 운행 요청이 재잠금 뒤 출발하는 것을 확인했다. 정면 닫힘/열림·사선·접촉 PNG를 확인했고 오류는 0건이다. 과속 트립·RST·구출 운전 검증도 통과했다.
- `THREE is not defined`가 재발하면 검증 로그의 `REQUEST FAILED`를 먼저 확인한다. 이번 원인은 샌드박스의 CDN 접근 차단이었으며 네트워크 허용 환경에서 동일 앱 코드로 통과했다.
- 현재본 PC 성능은 정지·회전 중앙값 33.3ms, 운행 33.4~49.9ms(3회), 로프 형상 재생성 0회다. 측정 조건과 미완료 항목은 [ROADMAP.md](ROADMAP.md)의 카 도어 인계 기록을 따른다. 실제 S22 조작·성능은 미검증이다.

- `node tools/verify_car_door.mjs`: 문짝 101자세, 해정 101자세, 베인/롤러 접촉, 다른 층 문 유지, 벨트 감속비·드럼/안내 풀리 회전량, 벽 간극, 가이드슈 지지, 실 높이/간극, 층간 개방 차단, 정상 운행, 비상정지·복귀, 터치 에뮬레이션.
- `SIMULATOR_URL=http://127.0.0.1:5500/index.html`을 지정하면 Live Server에 접속하며 캐시를 비활성화한다. `.shot-car-door/report.json` 및 PNG에 결과를 저장한다. 도면 비교용 분리 화면은 검증 브라우저 안에서만 적용된다.
- 기존 `verify_overspeed.mjs --shadows --detail-view`로 과속 트립·RST·구출운전을 확인한다. 실제 모바일 기기 성능은 에뮬레이션과 구분하며 미검증 상태를 유지한다.
- 기존 `verify_car_panels.mjs`는 현재 코드에 없는 `loadSensorBody`를 기대하므로 하중센서 검사에서 중단된다. 카 실 변경에 대한 실 간극/상면/홈 검사는 새 도어 도구에서 별도로 수행한다.
