# 이동케이블 · 종단 안전장치 (부품설계.pdf 184~204p)

## 구형 일렬 종단 스위치 (2026-09-17, 아래 3본 캠 기록보다 우선)

- 사용자 사진 `스크린샷 2026-09-17 012658.png` 기준으로 레일 클립 → 수평 취부 암 → 개별 스위치 구조를 적용한다. 피트부터 `DFL → DLS → DSD … USD → ULS → UFL`, 여섯 롤러 중심은 같은 X/Z 수직선이다.
- 기존 서로 다른 길이·레인의 캠 3개 대신 2560mm 공용 캠 한 개를 카 스타일에 단다. `index.html`의 `TERMINAL_CAM`이 단일 원본이며, `CAM_VANES`의 세 키는 호환용으로 같은 객체를 참조한다.
- 일렬 본체가 겹치지 않도록 리미트·파이널 중심 간격은 180mm다. 리드인 시작은 착상면에서 각각 100mm·280mm, 완전 눌림은 160mm·340mm로 표현한다. 이는 이 시뮬레이터의 재구성 값이며 기존 MR 교재의 40mm·95mm를 구형 장치의 설치 규격으로 옮겨 쓰지 않는다. 감속 시작 1500mm는 유지한다.
- 스위치는 은색 다이캐스트 본체, 어두운 전면 커버, 적갈색 헤드, 금속 레버, 고무 롤러, 글랜드·체결 나사·정리된 배선으로 표현한다. 레버 회전축과 롤러 중심을 공용 캠 중앙에 맞춘다.
- 외부 참고: [Schumacher 부품 카탈로그](https://www.schumacherelevator.com/wp-content/uploads/Manlift_PartsCatalog.pdf)의 레일 클립·취부 브라켓·롤러 레버 구성, [MCE 구형 제어기 설명서 §2.4.3.2](https://moen.nidec.com/elevators/-/media/Project/Nidec/NidecElevator/MCE/PDFs/Legacy-Control-Manuals/VVMC-SCR-Turbo-DF-Rev-F1.pdf)의 감속 유지 및 오버런 구간 리미트·파이널 유지 관계. 특정 제품 전체를 복제한 모델은 아니다.
- `node tools/verify_travel_cable.mjs`로 공용 캠 수량, 본체 간극, 상하 순서·눌림 유지, 이동케이블 회귀를 확인한다. 종단 플래그를 운행 FSM이 읽지 않는 기존 범위는 유지한다.

2026-09-11: 사용자 현장 사진 기준의 층별 평판과 카측 3단 착상기를 추가했다. 아래 과거 기록의 “착상센서/층별 차폐판 미설치” 설명은 [LEVELING-SENSORS.md](LEVELING-SENSORS.md)로 대체한다. 종단 안전장치 6개와는 별도 설비다.

### 이동케이블 실사 형태 보정

- CCTV 시공 사진의 카 하부 인입을 참고해 기존 드럼과 길게 돌출된 레일/카측 새들을 제거했다. 작은 취부판·그립과 꼬리를 짧게 마감한 검정 밴드만 고정 구간에 둔다. 자유 U자 구간에는 돌출물을 두지 않는다.
- 외피는 회색 PVC를 75×8mm, 모서리가 둥근 편평 단면으로 표현한다. U자 반지름은 120mm다. 치수는 시뮬레이터 재구성 값이며 특정 업체 제품 치수의 복제는 아니다.
- 카 하부 그립 → 바닥 아래 인입 → 카 외판 옆 → 상부 정션박스 경로로 연결한다. 정션박스는 카 그룹에 종속된다. CCTV 카메라와 전용 영상 케이블은 향후 작업 범위다.
- 고정단은 행거 위에서 벽면으로 붙어 제어반에 연결된다. `TC_WALL_X`, `TC_SIDE_X`가 벽·카 외판 이격의 원본이다. 임의 스플라인 오버슈트 대신 선분과 짧은 곡선으로 모서리만 둥글게 연결한다.
- Three.js에서 단면과 경로를 직접 생성한다. 가동부는 기존 길이 보존 식으로 정점만 갱신하므로 Blender 정적 메시로 바꾸지 않았다. `travelCableProfile`, `createTravelCableRun`, `addTravelCableGrip`, `addTravelCableBand`가 형상 공통 함수다.
- 검증: `node tools/verify_travel_cable_shape.mjs`. 전 층·오버런에서 길이와 간극, 외피의 실제 바운딩박스, 정션박스 카 추종, 기존 종단 스위치 6개 보존을 확인한다. `.shot-tc-real-*.png` 중 under/side/hanger는 주변 부품을 숨긴 검증용 절개 시점이다. 이전 `verify_travel_cable.mjs`는 과거 자석식 센서 상수를 참조하므로 현재의 MR 스위치 계약에는 맞지 않는다.
- 사진 참고: https://dvor24.ru/blog/videonablyudenie-v-lifte/montazh-kamery-v-lifte-po-provodam-poshagovaya-instruktsiya . 사용자 제공 네이버 글은 접근 실패로 직접 확인하지 못했다.

- 사용자 요청으로 특정 제조사 배선 구성을 단순화했다. 이동케이블은 회색 외피로, 제어반 방향인 좌측에 배치한다. 기존 조속기·종단 센서 위치는 유지한다.
- 이동케이블 Z 레인은 `CAR_RAIL_Z + 0.65`에서 시작하여 기존 센서와 취부 암을 피한다. 좌측 행거·카측 배선도 함께 반영한다. 길이 보존 및 피트 300mm 여유 계산은 유지한다.
- 통신 분기박스·피트 리모컨·미결선 코일 대신 검정 도어 접점선과 검정 조명선을 사용한다.
- `MR_설계.pdf` 파일 페이지 133~135의 세로 금속 박스 형상을 참고했다. 하부는 조명 토글과 적색 ESTOP, 상부는 조명 토글만 둔다. 높이는 문서의 500mm 대신 사용자 지정인 각 종단 승강장 바닥 +1m다.
- 두 박스는 좌측 벽면의 동일 X/Z에 설치하며 피트 사다리 옆으로 360mm 떨어진다. 피트와 각 층에 가로 LED를 한 개씩 둔다.
- 단일 원본은 `index.html`의 `TC_*`, `PIT_REMOTE_Y`, `TOP_LIGHT_SWITCH_Y`, `SHAFT_SWITCH_Z`, `SHAFT_LIGHT_Z`다. 박스 버튼은 이번 범위에서 시각 형상만 구현한다.
- 회색 외피 참고: https://static.datwyler-itinfra.com/assets/Downloads/DATWYLER_Catalogue_Elevator_2021_06_en.pdf . 가로 벽부등 형식 참고: https://sirijaya.com/product/sfb2-slim-batten/ . 검정 배선과 배치 수량은 사용자 요청이다.

## 종단 안전장치 스위치 방식 변경 (2026-09-10, 아래 16.7·16.8 센서 방식 기록보다 우선)

`MR_설계.pdf` 파일 137~138p(책 135~136p) **16.8 CAM ASSY 및 FLS ASSY 설치**를 기준으로
자석 센서(SLD)·카 천장 UDFL 스위치 방식을 **카 캠 + 레일 고정 스위치** 방식으로 바꿨다.

- 137p 1항 "CAM ASSY를 카 스타일에 고정" → `elevator.js buildCarCabin()` §7 `terminalCamAssy`.
  통판이 아니라 **파이프 3본**(감속 2560mm · 리미트 820mm · 파이널 720mm)이다. 타격면은 6t 평철,
  뒤는 Ø18 원형 파이프. Z 레인(`FLS_PAIR_DZ`)이 달라 자기 스위치만 밟는다.
  원본은 `index.html`의 `CAM_VANES`. 하강 시 각 가닥 **하단**, 상승 시 **상단**이 트립점이다.

  스위치는 레일에 남고 카가 지나가며 밟는다. 자석판·자석센서는 더 이상 만들지 않는다.

## 1. 좌우 배치 계약 — 이건 먼저 읽어야 한다

186p [우횡락]/[좌횡락] 평면도의 규칙은 다음 하나다.

> **조속기(GOV)와 이동케이블(T-Cable)은 같은 쪽 레일,
> 파이널 리미트(FLS)·착상(LCD)·강제감속(SLD)은 반대쪽 레일.**

이 프로젝트의 조속기는 `GOV_TENS_X = +1.4275`(우측)이므로 [좌횡락]에 해당한다.

| 장치 | 이 프로젝트 배치 |
| --- | --- |
| 조속기 · 이동케이블 | **우측(+X)** 카 레일 |
| 파이널 리미트 · 강제감속 | **좌측(−X)** 카 레일 |
| 승강로 벽면 하네스 · 제어반 · 피트 리모컨 | **좌측 벽면** (승강로를 두르는 벽이 좌측 하나뿐) |

착상센서(LCD)는 교재에도 "사이드 오픈만 적용"이라 적혀 있고 이 프로젝트는 중앙개폐라
설치하지 않는다. 층 확인은 SLD 판에 같이 붙는 **FLT_CFM 자석**이 담당한다.

## 2. 수치 원본은 `index.html` 한 곳뿐이다

승강로측(레일 고정)과 카측(톱빔 고정)을 서로 다른 파일이 만들기 때문에,
공유 좌표를 양쪽에 하드코딩하면 반드시 어긋난다.
계약 상수는 전부 `index.html`의 **"종단 안전장치 · 이동케이블 공용 계약"** 블록에 있다.

주요 상수와 근거:

| 상수 | 값/식 | 근거 |
| --- | --- | --- |
| `CAR_RAIL_Z` | `CAR_CTR_Z + 0.04` | 카 레일 배면 중심. `buildGuideRails()`가 이 값을 쓴다 |
| `RAIL_BRACKET_Y` | 1.35 + 2.7·n (6단) | 레일 브라켓 취부 높이. 캠·자석판 암이 이 밴드를 피한다 |
| `FLS_LEVER_L` | 0.050 | 고정축~롤러축 48~52mm (194p) |
| `FLS_TRIP_ANGLE` | 60° | 동작각 50~70° (197p) |
| `FLS_OVERTRAVEL` | 0.095 | 종단 착상면 ±90~99mm (196~197p **최종 조정**) |
| `FLS_CAM_FACE_X` | `FLS_PIVOT_X − (r + L·cosθ)` | 동작각에서 **역산**. 롤러가 완전히 밀렸을 때 롤러 뒷면 = 캠 면 |
| `FLS_CAM_BEND_LO/UP` | 종단 착상면 ∓`FLS_OVERTRAVEL` + `FLS_ROLLER_LY` | 캠 절곡부 높이 |
| `SLD_DIST` | 1.50 | 60m/min LA = LB = 1500mm (200~201p LENGTH TABLE) |
| `SLD_GAP` | 0.018 | 자석 ↔ 자석센서 20mm 이하 (204p) |
| `TC_PIT_CLEAR` | 0.30 | 최하층 곡면 최하단 = 피트 바닥 +300±50mm (188p) |
| `TC_HANGER_UP` | 1.00 | 해치 케이블 행거 = B 지점 카 바닥 +1,000mm (187p) |

### ★함정 1 — 196p의 "235mm"는 최종 기준이 아니다

196p에는 두 기준이 나온다.

* **판넬 조립 전 가설치**: 최하층 바닥레벨에서 탑빔 상단면 ↔ 하부 캠 절곡부 235mm
* **최종 조정**: 최하층 바닥레벨 −90~99mm 지점에서 UDFL 스위치가 동작

두 값은 톱빔 높이가 교재 기종과 같을 때만 일치한다.
이 프로젝트의 톱빔은 `chH = 0.14` 라 235mm를 그대로 박으면 롤러가 톱빔 하부 플랜지
높이로 내려가 스위치를 매달 자리가 없다.
**원본은 최종 조정값(±90~99mm)이고, 235mm는 주석으로만 남긴다.**

### ★함정 2 — 톱빔 "상면"에 카측 장치를 올리면 자리가 없다

톱빔 상면(로컬 Y `chY + chH/2` = 1.6075) 바로 위에는 이미 두 가지가 있다.

* 상부 가이드 슈 — 로컬 X −1.2875~−1.1345, **Z −0.043~0.123**
* 안전 난간대 베이스 가드 — 좌측 베이스 로컬 X −1.17~−1.145, **Z −0.10~0.40**

그래서 취부 암 경로를 이렇게 갈랐다.

* **UDFL**: 톱빔 상면 + 5mm, 암 시작 Z = −0.075(**후면 C채널 상단**) → 가이드 슈 앞으로 안 간다.
* **SLD ASSY**: 상면이 아니라 **톱빔 중심 높이**(`SLD_SENSOR_LY = CAR_H/2 + 0.36`)에서
  전면 C채널 웹에 물려 앞으로 나간다. 그래야 가이드 슈·베이스 가드 아래로 지나간다.

### ★함정 3 — 캠·자석판 암은 레일 브라켓 6단과 같은 공간을 쓴다

레일 브라켓은 레일 배면(−1.3125)에서 좌측 벽(−1.665)까지, Z −0.313~−0.113 을 채운다.
캠 판·자석판은 Z 레인이 달라 안 부딪히지만 **취부 암은 그 Z 구간을 가로지른다.**
`buildLimitSwitches()`의 `clearOfBracket()`이 취부 높이를 밴드(±130mm) 밖으로 밀어낸다.
하부 캠의 아래쪽 암이 실제로 4.08 → 4.18 로 밀려난다.

## 3. 이동케이블 길이·곡면 계약

### B 지점과 해치 케이블 행거 (187p)

187p 2항: "카운터웨이트 프레임 충돌판과 카 바닥이 같은 높이인 상태에서 1,000mm 상부".
B 지점은 상수로 박지 않고 **실제 카·균형추 그룹 위치에서 역산**한다.
균형추는 카와 반대로 같은 양 움직이므로 carY에 대한 1차식이 된다.

```
카 바닥(carY − CAR_H/2) = 균형추 충돌판(cwtY0 − (carY − carY0) − CWT_H/2)
→ carY_B = (cwtY0 + carY0 + (CAR_H − CWT_H)/2) / 2
→ 행거 Y = carY_B − CAR_H/2 + 1.000            (현재 값 7.730m)
```

`CAR_DEPTH_SCALE`이나 층고를 바꿔도 행거가 알아서 따라간다.

### 총 길이 (188p 5항)

"카가 최하층일 때 곡면 최하단부가 피트 바닥 +300±50mm" 조건으로 총 길이를 역산한다.

```
yc(곡면 중심) = 피트바닥 + 0.30 + R
L = (행거Y − yc) + πR + (최하층 카행거Y − yc)   → 현재 8.692m
```

길이가 정해지면 카가 움직일 때마다 `refreshTravelCable()`이 같은 식을 yc에 대해 푼다.

```
yc = (행거Y + 카행거Y + πR − L) / 2
```

카가 행거보다 위로 올라가면 곡면도 같이 올라가고(카가 최상층일 때 최하단 5.995m),
고정측 가닥이 짧아진다. 이건 실물과 같은 거동이다.

### 메시

편평형 케이블이라 원형 튜브가 아니라 **단면 55×18mm 리본**이다.
샘플 수 `TC_SEGS = 120`을 고정해 두고 위치 속성만 갱신하므로
렌더 루프에서 지오메트리를 새로 만들지 않는다(AGENTS.md 규칙).
폭은 항상 월드 X 축, 두께는 진행방향 법선 방향이다.

## 4. 갱신 경로

카 위치가 바뀌는 모든 경로(자동 운행 / 점검 운전 / 과속 낙하)는 `refreshRopes()`를 거친다.
그래서 호출점은 `refreshRopes()` 끝 한 곳뿐이다.

```
refreshRopes()
  → refreshTravelCable()     이동케이블 곡면 중심 재계산 + 리본 정점 갱신
  → refreshTerminalDevices() UDFL 레버 각도 + SLD 자석 근접 판정
```

`refreshTerminalDevices()`는 `elevatorState.finalLimitActive / slowdownActive / floorConfirm`
플래그만 채운다. **운행 FSM은 건드리지 않는다.** 이 플래그를 읽는 곳은 아직 없다.

## 7. 이 범위에서 만들지 않은 것

* **착상센서(LCD)** — 교재에도 "사이드 오픈만 적용". 이 프로젝트는 중앙개폐라 해당 없음.
* **층별 착상 차폐판** — 16.8은 종단(최상·최하)의 SLD/FLT_CFM 자석만 다룬다.
  층마다 붙는 착상판이 필요하면 `buildShaftLandingDevices()` 스텁에 별도로 올려야 한다.
* **홀버튼 본체 결선** — 189p 4~7항 중 승강로측 그로밋·인입선까지만. 홀버튼 함은 기존 형상 유지.
* **비상통화 장치 본체** — 190p 8항이 "케이블만 내려둔다"라 캡 씌운 미결선 케이블만 있다.
* **17. 카 판넬 설치(205p~)** — 이번 범위 밖.
